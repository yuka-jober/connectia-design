# PRD — 이벤트 만들기 입력창 (사업자용) v2

> 이 문서는 `event-input-v1.html` 프로토타입의 실제 동작을 기반으로 역으로 작성한 사양서입니다.
> 사용자(사업자)가 화면에서 실제로 무엇을 채워야 하고, 무엇이 미리 채워져 있으며, 입력 중에 어떤 일이 일어나는지를 정의합니다.

---

## 0. 한 줄 요약

병원이 **랜딩 페이지를 한 화면에서 끝까지 채워 발행**할 수 있는 입력창. 필수 항목만 채우면 발행되고, 나머지는 기본값이 깔려 있다.

---

## 1. 화면 구성

| 화면 | 진입 | 역할 |
|---|---|---|
| **입력 화면** (기본) | 처음 진입 시 | 사업자가 정보를 채움 |
| **미리보기 화면** | 상단 "미리보기" 버튼 | 고객이 보는 랜딩이 실시간으로 어떻게 보이는지 확인 |

- 입력 화면 상단: 뒤로 / 가운데 "이벤트 만들기" / 우측 "미리보기" (텍스트 버튼)
- 미리보기 화면 상단: 뒤로 / 가운데 "미리보기"
- 입력 화면 하단: sticky "발행하기" 버튼 (필수 항목 모두 채워야 활성화)
- 미리보기 화면 하단: 고객이 보는 sticky CTA (disabled 상태로 노출)

---

## 2. 진행 상태 카드 (상단 고정 영역)

입력창 가장 위에 카드 형태로 노출.

- 제목: **"필수 항목 채우기"**
- 카운트: `X / 4` (현재 채운 필수 / 전체 필수)
- 막대형 진행 바 (primary 색)
- 보조 문구: "필수 항목만 채우면 이벤트를 발행할 수 있어요"

### 실시간 동작
- 입력할 때마다 필수 카운트와 진행 바가 즉시 업데이트
- 4개 모두 채워지면 하단 "발행하기" 버튼이 활성화됨

---

## 3. 입력 섹션 정의

> 표기: ★필수 / ●기본값(수정가능) / ○선택 / ⓘ안내(입력 불가)
> 카드 UI 대신 **섹션 사이 1px 디바이더**로 구분.

### 섹션 1 — 기본 정보
고객이 보는 랜딩에 그대로 노출되는 정보.

| 항목 | 타입 | 구분 | 기본값 / 플레이스홀더 | 실시간 동작 |
|---|---|---|---|---|
| **신청 기간** | 시작일 ~ 종료일 (date input) | ★필수 | 빈칸 | 두 날짜 모두 채워지면 진행률 +1. D-Day 자동 계산 ("총 N일 동안 진행돼요"). 종료일이 시작일보다 빠르면 빨간 안내 |
| **대표 이미지** | 1~5장 업로더 (3열 그리드) | ★필수 | 빈 "사진 추가" 타일 1개 | 1장 이상이면 진행률 +1. 첫 장은 "대표" 표기. 5장 도달 시 추가 버튼 숨김. 호버 시 삭제 가능 |
| **이벤트 제목** | 한 줄 텍스트 | ★필수 | placeholder: "예) 라식·라섹 1명 전액지원" | 입력 시 미리보기 hero 제목으로 즉시 반영 |
| **누구를 위한 건가요?** | 한 줄 텍스트 | ★필수 | placeholder: "예) 서울시립대 재학생·졸업생 한정" | 입력 시 미리보기 대상 줄에 즉시 반영 |
| **자격 조건** | 칩 추가형 (chip editor) | ○선택 | 비어 있음 | "조건 추가" 버튼 → 입력창 노출 → Enter 또는 "추가" 클릭으로 칩 생성. 칩 X 버튼으로 삭제 |
| **이벤트 설명** | 장문 (textarea) | ○선택 | placeholder: "이벤트 진행 절차나 안내사항을 적어주세요" | 미리보기 "이벤트 안내"에 즉시 반영. 길어지면 랜딩에서 "더보기"로 접힘 |

### 섹션 2 — 신청 폼 구성
고객이 신청 버튼을 눌렀을 때 답하는 항목 구성.

#### 상단 안내 박스 (ⓘ)
- 라벨: **"이름·연락처를 기본으로 받아요"**
- 회색 배경 박스 + info 아이콘. 입력 불가.
- 컴플라이언스상 위치·문구 모두 고정. 사업자가 못 건드림.

#### 관심 항목 — ○선택
보더라인으로 묶인 카드. 안에 두 개의 서브 항목:

| 서브 항목 | 타입 | 기본값 | 동작 |
|---|---|---|---|
| **질문** | 한 줄 텍스트 | "관심 시술" | 사업자가 수정 가능. 빈칸이면 미리보기에서 기본값 사용 |
| **선택지** | 칩 추가형 | 비어 있음 | "선택지 추가" 버튼으로 칩 생성. 2~5개 권장 (제한은 아님) |

### 섹션 3 — 신청 버튼·완료 화면
모두 기본값이 미리 채워져 있음. 그대로 발행해도 동작함. ●기본값.

| 항목 | 타입 | 기본값 | 동작 |
|---|---|---|---|
| **신청 버튼 문구** | 한 줄 텍스트 | "이벤트 신청" | 미리보기 하단 CTA에 즉시 반영. 빈칸이면 "이벤트 신청"으로 폴백 |
| **예상 연락 시점** | 한 줄 텍스트 | "1영업일 이내" | 완료 화면에 노출 |
| **연락 방식** | 다중 선택 칩 | 전화 / 카카오 알림톡 (둘 다 선택됨) | 칩 클릭으로 토글. 사용 가능한 선택지: 전화 / 카카오 알림톡 / 문자 / 이메일 |

---

## 4. 필수/기본값/선택 시각화

| 구분 | 표기 방식 |
|---|---|
| 필수 | 라벨 옆 빨간 **`*`** |
| 선택 | 라벨 옆 회색 **`(선택)`** |
| 기본값 | 별도 표기 없음 (값이 미리 채워져 있는 것으로 구분) |
| 안내(입력불가) | 회색 박스 + info 아이콘으로 일반 입력 칸과 시각적으로 분리 |

---

## 5. 실시간 미리보기 동기화

입력창에서 값이 바뀔 때마다 미리보기 화면도 즉시 갱신.

| 입력 항목 | 미리보기 반영 위치 | 빈 상태 표시 |
|---|---|---|
| 대표 이미지 | hero 슬라이더 (1장이면 단일, 여러 장이면 가로 스크롤 + 우측 하단 `1 / N` 카운터) | placeholder 영역에 "사진을 추가하면 여기에 보여요" |
| 이벤트 제목 | hero 헤드라인 | 회색 "이벤트 제목" |
| 대상 | hero target 줄 | 회색 "대상 문구" |
| 신청 기간 | 날짜 카드 | "기간을 선택해주세요" |
| 자격 조건 | "이런 분이라면 신청해보세요" 체크리스트 | 이탤릭 "자격 조건을 추가하면 여기에 표시돼요" |
| 이벤트 설명 | "이벤트 안내" 본문 | "설명을 입력하면 여기에 표시돼요" |
| 신청 버튼 문구 | 미리보기 하단 sticky CTA (disabled) | "이벤트 신청" |

### 미리보기에서 자동 노출되는 (사업자가 못 건드리는) 요소
- 병원명 (`첫눈애안과`) — 사업자 계정에서 자동
- 별점 `★ 5.0 · 후기 28개` — 시스템 연동
- `커넥티아 공식 이벤트` 뱃지 — 자동
- 미리보기 화면 자체의 "이름·연락처·약관 동의" 입력 흐름 — 자동

---

## 6. 발행 동작

- 하단 sticky **"발행하기"** 버튼
- 필수 4개(신청 기간 / 대표 이미지 / 이벤트 제목 / 대상) 모두 채워지기 전까지 **disabled**
- 다 채워지면 활성화. 클릭 시 발행 (목업: alert)

---

## 7. 입력 칸 종류와 인터랙션 정리

| 입력 종류 | 사용처 | 인터랙션 |
|---|---|---|
| 한 줄 텍스트 (`.input`) | 제목/대상/관심 질문 등 | 일반 typing |
| 장문 (`.textarea`) | 이벤트 설명 | 일반 typing, 높이 가변 |
| 날짜 (date input) | 신청 기간 | OS native picker |
| 이미지 업로더 (3열 그리드) | 대표 이미지 | 타일 클릭 → 추가 (현재는 색상 그라데이션 목업). 호버 시 삭제 X 버튼. 첫 장 "대표" 칩 |
| 칩 추가형 | 자격 조건, 관심 항목 선택지 | "+ 추가" 버튼 → 입력창 노출 → Enter / 추가 버튼으로 확정. 각 칩의 X 버튼으로 삭제 |
| 다중 선택 칩 | 연락 방식 | 칩 클릭으로 on/off 토글 (선택된 칩은 primary-light 배경) |

---

## 8. 의도적으로 빠진 것 (이번 범위 밖)

- ❌ **완료 메시지 칸** — 메시지 자체는 시스템 기본 문구로 발행. 예상 연락 시점·연락 방식만 사업자가 조절
- ❌ **이름·연락처·약관 동의 폼 직접 편집** — 컴플라이언스 고정. 시스템이 자동 포함
- ❌ **신청 폼에 자유 입력 항목 추가** — 컴플라이언스·이탈 리스크. 늘어나면 "준비된 선택지 켜기" 방식으로 추가 검토
- ❌ **자동 안내 섹션** ("이건 자동으로 들어가요") — 디자인상 시야가 너무 분산되어 빼고, 자동 항목은 미리보기를 통해 확인하도록 유도

---

## 9. 사업자가 실제로 채우는 것 (요약)

- **반드시 채워야 하는 4가지**: 신청 기간, 대표 이미지(1장 이상), 이벤트 제목, 대상
- **선택**: 자격 조건, 이벤트 설명, 관심 항목 질문·선택지
- **기본값이 깔려있어 안 건드려도 되는 것**: 신청 버튼 문구, 예상 연락 시점, 연락 방식(전화·카카오 알림톡 기본 선택)
- **자동/고정으로 시스템이 처리하는 것**: 병원명·이름·연락처·약관 동의·별점·후기·공식 뱃지·D-Day·신청자 수
