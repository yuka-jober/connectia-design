# 재료로 AI 초안 만들기 — 개발 기획서

2026-10-12 · JOBER

게시글 에디터 안에서 재료(따라할 지난 글, 메모와 링크, 사진·영상)를 한 번에 넣으면, AI가 실제 편집 가능한 블록으로 초안을 채워 주는 기능이다. AI 도구에서 글을 쓰고 복사해 오는 왕복을 없애는 것이 목표다.

- 프로토타입: [post-write.html](post-write.html)
- 시연 영상(38초): [demo.mp4](demo.mp4)

## 배경과 목표

운영자는 지금 다른 AI 도구에서 글을 쓰고 커넥티아로 복사해 온다. 실제로 시간이 드는 일은 문장보다 재료 정리다.

2026년 10월 서울시립대 총동문회 10월호를 직접 올려 보며 확인한 작업량은 다음과 같다.

- 재료 출처 5곳: 행사 페이지 링크 1개, 사진 폴더 3개(사진 100장 이상), 영상 2개(최대 63MB), 지난 3월호의 동문 소식
- 손이 간 일: 중복 사진 빼기, 장면 고르기, 비율별 캐러셀 나누기, 영상 썸네일 지정, 지난 호 구조 맞추기
- 사람이 판단한 일: 무엇을 메인으로 할지, 어떤 섹션을 넣을지, 보이는 모양

목표는 재료를 에디터 안에서 한 번에 넣고, 편집 가능한 초안을 블록으로 받는 것이다. 성공 기준은 운영자가 다른 AI 도구를 열지 않고 초안을 완성하는 것이다.

## 사용자 흐름

1. 글쓰기를 연다. 본문이 비어 있으면 캔버스에 "재료로 초안 만들기" 입구 카드가 보인다. 툴바 끝 AI 초안 버튼으로도 언제든 연다.
2. [재료 넣기]를 누르면 재료 시트가 열린다.
3. 따라할 글: [글 고르기]로 이 게시판의 지난 글 하나를 고른다. 고른 글은 칩으로 표시된다.
4. 메모: 어떤 글인지 자유롭게 적는다. 페이지 주소를 붙여 넣으면 메모 아래에 제목 칩으로 인식된다.
5. 사진·영상: 여러 장을 한 번에 추가한다. 개수가 표시된다.
6. [초안 만들기]를 누른다. 재료가 하나라도 있어야 활성화된다.
7. 시트가 닫히고, 제목과 본문 자리에 블록 모양 스켈레톤이 보인다.
8. 초안이 실제 에디터 블록(제목, 헤딩, 문단, 사진, 캐러셀, 영상, 링크 블록)으로 채워진다.
9. "초안을 채웠어요" 토스트와 [되돌리기]가 뜬다. 되돌리면 직전 상태로 돌아간다.
10. 운영자가 블록을 직접 고치고 [완료]로 게시한다. 게시는 항상 사람이 누른다.

## 화면 구성과 상세 스펙

기존 글쓰기 화면에 입구 2개, 시트 2개, 생성 상태, 토스트가 추가된다. 기존 서식·미디어·링크 블록, 공지, AI 학습 토글은 그대로다.

| 요소 | 위치 | 동작과 규칙 |
| --- | --- | --- |
| 입구 카드 | 빈 캔버스 상단 | sparkles 아이콘 + "재료로 초안 만들기" + [재료 넣기]. 본문에 내용이 생기면 숨김, 다시 비면 다시 보임 |
| AI 초안 버튼 | 에디터 툴바 삽입 영역 맨 끝 | sparkles 아이콘. 본문 유무와 상관없이 재료 시트를 연다 |
| 따라할 글 | 재료 시트 첫 항목 | [글 고르기] → 지난 글 목록 시트. 1개만 선택, 고르면 칩(파일 아이콘 + 제목 + ✕)으로 바뀌고 버튼은 숨김 |
| 지난 글 목록 | 두 번째 바텀시트 | 제목 + 게시일, 최신순. 뒤로 버튼으로 재료 시트로 복귀 |
| 메모 | 재료 시트 | 4줄 textarea. 플레이스홀더에 예시 4줄(아래 문구). 붙여 넣은 URL을 감지해 아래에 페이지 제목 칩으로 표시. 칩은 메모를 따라가며 ✕ 없음 |
| 사진·영상 | 재료 시트 | 라벨 옆에 개수. 정사각 썸네일 그리드(4열), 영상은 재생 아이콘 오버레이. 추가 타일로 여러 장 선택 |
| [초안 만들기] | 재료 시트 하단 | 따라할 글·메모·사진 중 하나라도 있어야 활성 |
| 생성 중 스켈레톤 | 제목 자리 + 캔버스 | 제목 줄, 문단, 큰 이미지 박스 모양이 펄스. 실제 생성이 끝날 때까지 |
| 결과 토스트 | 하단 | "초안을 채웠어요" + [되돌리기], 4초 |

메모 플레이스홀더 문구(확정):

```
어떤 글인지 자유롭게 적어 주세요
예) 10월 소식, 청춘건배를 메인으로
오피스챗은 박종면 선배(토목 88)
참고할 페이지 주소도 붙여 넣을 수 있어요
```

그 밖의 보조 설명 문구는 넣지 않는다(디자인 원칙).

## AI 생성 규칙

AI는 틀려도 눈에 보이고 쉽게 고칠 수 있는 일만 하고, 틀리면 사고가 나는 일은 사람에게 남긴다.

| 재료 | AI가 쓰는 방식 |
| --- | --- |
| 따라할 글 | 섹션 순서와 헤딩 스타일을 따른다. 매호 반복되는 섹션(예: 동문 소식, 회장 AI 대화)은 내용까지 가져온다 |
| 메모 | 글의 주제, 메인과 강조점, 사람 이름·직함의 기준이 된다. 메모가 따라할 글보다 우선한다 |
| 메모 안 링크 | 페이지를 읽어 날짜, 장소, 인원 같은 사실을 가져온다. 본문에는 링크 블록(버튼형)으로도 넣는다 |
| 사진·영상 | 섹션별로 배치한다. 대표 사진 1장을 크게 두고, 나머지는 같은 비율끼리 캐러셀로 묶는다. 같은 장면의 연사 사진은 1장만 쓴다 |

AI가 하지 않는 것:

- 재료에 없는 사실(이름, 직함, 숫자, 날짜, 행사 결과)을 지어내지 않는다. 빈 곳은 비워 둔다.
- 게시하지 않는다. 초안은 에디터에만 들어간다.
- 기존 본문을 덮어쓰지 않는다. 본문이 있으면 아래에 이어 붙이고, 제목이 있으면 제목은 그대로 둔다.
- 지난 글에서 가져온 반복 섹션은 내용을 새로 쓰지 않고 그대로 가져온다. 최신화는 사람이 한다.

헤딩은 실서비스 에디터(tiptap)의 heading 노드로 넣는다. 프로토타입은 헤딩 블록이 없어 굵은 글씨로 표현했다.

## 제약과 예외 처리

10월호를 실제로 올리며 부딪힌 현재 에디터의 한도다. 초안 생성은 이 한도 안에서 결과를 만들어야 한다.

| 상황 | 현재 동작 | 초안 생성 시 처리 |
| --- | --- | --- |
| 글 하나에 사진 20장 초과 | [완료]를 눌러야 "최대 20장" 에러 | 초안에 20장까지만 넣는다. 재료 시트에서 20장을 넘게 골랐을 때의 처리는 열린 질문 |
| 캐러셀 1개에 10장 초과 | 안내만 뜨고 뒤쪽 사진이 빠짐 | 초안은 캐러셀당 10장 이하로 나눠 만든다 |
| 비율이 다른 사진을 한 캐러셀에 | 사진이 늘어나 보임 | 같은 비율(16:9, 4:3, 9:16 등)끼리만 묶는다 |
| 큰 영상 | 63MB(4분 8초) 업로드 확인됨 | 업로드는 백그라운드로 진행하고 초안에는 자리부터 넣는다 |
| 영상 첫 화면이 검은색 | 썸네일이 검게 보임 | 알아볼 수 있는 프레임을 골라 썸네일로 지정한다 |
| 본문이 이미 있음 | 해당 없음 | 기존 글 아래에 이어 붙이고 제목은 유지한다 |
| 생성 실패 | 해당 없음 | 스켈레톤을 거두고 에디터를 생성 전 상태로 두며, 재료 시트 내용은 유지한다 |
| 되돌리기 | 해당 없음 | 초안 넣기 직전의 제목과 본문으로 복원한다. 빈 상태였으면 입구 카드도 다시 보인다 |

초안을 넣기 전에 사진 한도(20장)를 에디터에 표시하면 위 에러 대부분을 미리 막을 수 있다.

## 이번 범위 밖과 다음 단계

이번에는 "재료 넣기 → 초안" 흐름과 따라할 글만 만든다. 아래는 이 흐름 위에 얹을 다음 단계다.

1. 대화로 고치기: "청춘건배를 메인으로", "캐러셀을 비율별로 나눠줘" 같은 지시를 에디터 옆 입력창으로 받아 바로 반영한다.
2. 확인할 곳 짚기: AI가 쓴 문장 중 이름·숫자·날짜와 추측한 문장에만 표시를 달아, 게시 전에 그것만 훑게 한다.
3. 사진 자동 정리: 같은 장면 묶기, 대표 사진 추천, 비율별 캐러셀 분리, 남은 장수 표시.
4. 링크 블록: 썸네일을 누르면 원본 영상으로 가는 블록(버튼형/썸네일/카드형). 별도 프로토타입이 있고, 초안의 링크도 이 블록으로 들어간다.

## 개발과 정할 열린 질문

- [ ] 따라할 글의 "반복 섹션"을 어떻게 가려낼지: AI가 판단할지, 운영자가 섹션별로 "유지/비우기"를 고를지
- [ ] 지난 글 목록의 범위: 같은 게시판만인지, 내가 쓴 글 전체인지, 몇 개까지 보여줄지
- [ ] 메모 안 링크를 읽을 수 있는 범위: 커넥티아 내부 글만인지, 외부 페이지도 읽을지. 로그인이 필요한 페이지(예: 구글 드라이브 다운로드 제한 파일)는 어떻게 처리할지
- [ ] 재료 시트에서 사진을 20장 넘게 골랐을 때: 막을지, AI가 20장을 고를지
- [ ] 사진 분석(중복 제거, 장면 판단, 비율)을 업로드 전 클라이언트에서 할지, 업로드 후 서버에서 할지
- [ ] 큰 영상 업로드가 끝나기 전에 초안을 보여줄지, 기다릴지
- [ ] 생성 시간이 길 때(수십 초) 스트리밍으로 블록을 차례로 채울지
