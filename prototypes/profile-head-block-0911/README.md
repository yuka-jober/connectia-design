# 프로필 편집 — 블록형

프로필 편집 화면을 "고정 헤더 + 블록 목록" 이중 구조에서 **하나의 블록 목록**으로 통일한 작업.

- 승인 대기본: `review/profile-edit-block.html`, `review/profile-edit-block-empty.html`
- 출발점: 2025-08-21판 블록형 프로필 편집

---

## 1. 왜 바꿨나

이전 화면은 커버·프로필 사진·이름이 맨 위 고정 영역에 묶여 있고 나머지만 블록이었다.
편집 모델이 둘로 갈라져 있어서 요소마다 고치는 방법이 달랐다. 사진은 디자인 시트에서, 이름은 상단 다이얼로그에서, 링크는 블록을 눌러서 — 사용자가 "이건 어디서 고치지"를 매번 다시 배워야 했다.

이번 작업의 원칙 네 가지:

1. **본문에 보이는 것은 전부 블록.** 사진도 이름도 다른 블록과 똑같이 옮기고 지운다.
2. **배경은 블록이 아니다.** 커버는 콘텐츠가 아니라 페이지 바탕이므로 순서에 참여하지 않는다.
3. **진입점은 하나씩.** 무엇을 고치든 화면에서 그것을 직접 누른다.
4. **편집 화면에 브랜드색을 쓰지 않는다.** 사용자가 페이지 색을 자유롭게 바꾸는데 편집 UI가 브랜드색을 점유하면, 지금 보이는 색이 내 페이지 색인지 편집 도구 색인지 헷갈린다.

## 3. 블록

| 블록 | 페이지당 1개 | 비고 |
|---|---|---|
| 프로필 사진 | ○ | 자체 정렬 |
| 이름 | ○ | 이름 + 주소, 자체 정렬 |
| 링크 | | 버튼형 / 썸네일 / 카드형 |
| 텍스트 | | |
| 갤러리 | | 격자 / 가로 / 세로 |
| 구분선 | | |
| SNS | ○ | |
| 연락처 | ○ | |
| 링크 모음 | ○ | |
| 이벤트 | ○ | 컬렉션 |
| 게시판 | ○ | 컬렉션 |
| 리뷰 | ○ | 컬렉션 |

**페이지당 1개**인 블록은 이미 넣었으면 블록 추가 목록에서 흐리게 비활성된다.

**삭제** — 사진·이름 포함 전부 지울 수 있다. 지우면 블록 추가에서 다시 넣는다.
단 이벤트·게시판·리뷰는 **등록된 항목이 남아 있으면 삭제 버튼이 나오지 않는다.** 콘텐츠가 딸린 블록을 실수로 날리지 않게 하기 위해서다.

**빈 페이지** — 사진·이름·대화하기만 남으면 아직 "빈 페이지"로 보고 안내를 띄운다. 프로필 껍데기만 있는 건 페이지를 채운 게 아니라고 본다.

**대화하기 버튼**은 위치를 `프로필 안`으로 두면 블록처럼 순서에 참여한다. 다른 위치(하단 고정·코너)로 바꾸면 목록에서 빠지고, 다시 `프로필 안`으로 돌리면 직전에 있던 자리로 돌아온다.

---

## 4. 커버 (배경)

- **이미지를 등록했을 때만 보인다.** 없으면 영역 자체가 없고 블록이 화면 맨 위에서 시작한다.
- 커버가 없을 때는 **편집 중에만** 점선 등록 슬롯이 뜬다. 미리보기와 실제 페이지에는 아무것도 없다.
- 커버(또는 슬롯)를 누르면 블록과 같은 시트가 열린다 — 사진 변경/제거, 가장자리(기본 / 페이드).
- 커버 위에 프로필 사진이 걸쳐지던 **겹침 배치는 폐기**했다. 사진이 자유롭게 움직이는 블록이 된 이상, 커버와 붙어 있다는 전제를 유지할 수 없다.

## 5. 무엇을 어디서 고치나

| 고치는 것 | 진입점 |
|---|---|
| 프로필 사진 | 사진 블록 누르기 |
| 이름 · 주소 | 이름 블록 누르기 **또는** 상단 `이름·주소` |
| 배경 사진 · 커버 가장자리 | 커버 누르기 |
| 대화하기 버튼 | 대화하기 블록 누르기 → 디자인 `대화버튼` |
| 페이지 배경색 · 텍스트 색 | 디자인 `스타일` |
| 블록 모양 · 그림자 · 정렬 | 디자인 `블록` |

디자인 시트에 있던 `프로필` 탭(프로필 이미지·배경 이미지 업로드)은 없앴다. 이미지는 전부 화면에서 직접 눌러 고친다.

---

## 6. 이름과 주소

이름과 주소는 **이름 블록**과 **상단 `이름·주소`** 양쪽에서 고칠 수 있다. 이름 블록을 안 넣었거나 지운 경우 상단이 유일한 통로가 되므로 둘 다 남긴다. 한쪽에서 고치면 다른 쪽에도 바로 반영된다.

**주소는 쓸 수 있는 값일 때만 반영된다.** 입력하는 동안 중복을 검사해 `사용 중` / `사용 가능`을 띄우고, 이미 쓰이는 주소면 미리보기가 바뀌지 않는다. 이름은 입력하는 대로 바로 반영된다.

---

## 7. 정렬

정렬 축이 셋이고 서로 독립이다.

| 대상 | 어디서 | 값 |
|---|---|---|
| 프로필 사진 | 사진 블록 | 좌측정렬 / 중앙정렬 |
| 이름 + 주소 | 이름 블록 | 좌측정렬 / 중앙정렬 |
| 나머지 본문 블록 | 디자인 `블록` | 좌측정렬 / 중앙정렬 |

프로필 사진은 페이지 첫인상이라 본문과 따로 가고 싶은 경우가 많아 자체 정렬을 준다. 이름도 같은 이유로 분리했다.

전역 블록 정렬은 SNS · 텍스트 · 섹션 제목 · 연락처 · 리뷰 별점에 걸린다.

## 8. 컬렉션과 전체보기

이벤트 · 게시판 · 리뷰는 `노출 개수`(3 / 5 / 10)만큼만 본문에 보인다. 갤러리도 같은 성격이다.

**각 블록 우측 하단에 `전체보기`** 가 있고, 누르면 해당 목록 전용 화면으로 들어간다.
정렬 설정과 무관하게 항상 오른쪽에 붙는다 — 정렬은 *콘텐츠*를 어떻게 놓을지의 문제고, 전체보기는 *액션*이라 같이 움직일 이유가 없다.

### 랜딩 탭을 없앤 이유

원래는 페이지 위쪽에 `홈 / 갤러리 / 이벤트·행사 / 게시판 / 리뷰` 탭이 있고, 컬렉션 블록을 넣으면 자동으로 생겼다.

이번에 사진·이름까지 자유 블록이 되면서 **탭을 놓을 기준점이 사라졌다.** 맨 위에 고정하면 프로필보다 위로 올라가 순서가 뒤집히고, "프로필 아래"로 정하면 프로필 자체가 페이지 중간에 갈 수 있어 규칙이 성립하지 않는다. 옮길 수 있게 하면 중간에 끼어 어색해진다.

전체보기가 같은 역할을 **블록에 붙은 채로** 한다. 블록을 어디로 옮기든 진입점이 따라다니므로 위치 문제가 생기지 않는다. 그래서 탭은 폐기하고 켤 수 있는 경로도 두지 않았다.

### 그 밖에

- 정렬을 `직접 지정`으로 바꾸면 그 아래에 `노출 순서 변경`이 붙는다.
- **이벤트·게시판에는 블록 단위 AI 학습 설정이 없다.** 항목마다 따로 지정하기 때문이다. 리뷰는 방문자가 남기는 것이라 항목별 설정이 없어서 블록 단위로만 둔다.

## 9. 편집 중 화면

편집 중인 블록에 테두리를 두르지 않는다. 대신 **나머지를 흐리게 뒤로 물린다.** 커버, 다른 블록, ⊕ 슬롯, 레일이 함께 물러나고 편집 대상만 또렷하게 남는다. 시트가 올라올 때 함께 부드럽게 들어간다.

이렇게 한 이유는 **페이지 배경색을 사용자가 임의로 바꾸기 때문**이다. 테두리 방식은 어떤 색을 골라도 묻힐 수 있다 — 검정 테두리는 어두운 배경에서, 보라 테두리는 보라 배경에서 사라진다. 활성 블록에 아무 색도 쓰지 않으면 배경색이 무엇이든 상관없어진다.

**디자인 시트를 열면** 페이지가 축소돼 목업처럼 보인다. 목업 아래쪽은 라운딩 없이 시트 뒤로 이어져, 시트가 페이지를 덮고 있을 뿐이라는 인상을 준다.

## 10. 색 운용

### 편집 UI

바텀시트 안에서 브랜드색을 전부 걷어내고 무채색으로 바꿨다.

- 시트 `완료`, 디자인 시트 탭 — 검정
- 선택 상태 테두리(목업 타일 · 색상 스와치 · 블록 추가 hover) — 중간 회색. 순검정은 너무 무겁다
- 옵션 선택, 상단 칩 활성 — 옅은 회색 채움, 테두리 없음
- `노출 순서 변경` 버튼만 한 단계 진한 회색 — 같은 회색끼리 구분이 필요해서
- 버튼 테두리는 평상시 한 단계 옅게. 평소엔 조용하고 고른 것만 또렷하게

### 페이지 콘텐츠

**리뷰 별은 대화하기 버튼 색을 따라간다.** 색상 프리셋과 커스텀 색까지 그대로 반영된다. 브랜드 그라데이션을 고른 경우에는 보라색으로 표시된다.

### 디자인 시트 목업

위치·모양·그림자 목업은 전부 무채색으로 그린다. 대화버튼 위치 목업도 실제 버튼 색 대신 검정을 쓴다 — 위치를 고르는 그림이고, 색은 바로 아래 `색상` 항목이 따로 담당하기 때문이다.

## 11. 두 버전

화면 동작은 동일하고 초기 상태만 다르다.

- **`profile-edit-block.html`** — 블록이 채워진 상태 (사진 · 이름 · 연락처 · 구분선 · SNS · 텍스트 · 링크 · 갤러리 · 이벤트 · 게시판 · 리뷰)
- **`profile-edit-block-empty.html`** — 사진 · 이름 두 블록만 있는 신규 페이지. 커버 없음, 빈 페이지 안내 표시

---

## 12. 남은 것

- **`screens/board.html`의 리뷰 별** — 아직 브랜드색 고정이라, 편집 화면에서 색을 바꿔도 실제 페이지에는 반영되지 않는다. 이번 범위에서 제외했다.
- **어두운 배경에서의 편집 도구** — 배경을 아주 어둡게 바꾸면 레일 화살표와 ⊕ 삽입선이 묻힌다. 편집 UI 전반을 함께 봐야 하는 과제라 별도로 남긴다.
- 팀 승인 후 `screens/` 반영 + `SCREENS.md` · `PRODUCT.md` 갱신
