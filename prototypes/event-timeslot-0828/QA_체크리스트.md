# 청춘건배 기능 QA 체크리스트

배포 후, **청춘건배와 같은 구조의 가상 행사를 실제로 한 번 끝까지 굴려보는** 방식으로 확인한다.
화면을 하나씩 열어보는 점검이 아니라, 주최측 → 참가자 → 현장 순서로 실제 행사처럼 진행한다.

---

## 0. 시작하기 전에

### 준비물

| 항목 | 필요 수량 | 비고 |
|---|---|---|
| 테스트용 휴대폰 번호 | 6개 이상 | 팀원 동의는 번호마다 따로 받으므로 실제로 필요 |
| 휴대폰 기기 | 3대 이상 | iOS·Android 섞어서. 나머지는 링크 전달로 대체 가능 |
| 주최측 계정 | 1개 | 이벤트를 만들 계정 |
| 커뮤니티 **비회원** 계정 | 2개 이상 | 자동 가입을 확인하려면 아직 가입 안 된 사람이 필요하다 |
| 커뮤니티 **기존 회원** 계정 | 1개 | 중복 가입이 안 되는지 확인용 |
| 스태프 계정 | 1개 | 체크인 전용 링크만 받는 사람 |

### 시작 전 확인

- [ ] 알림톡 템플릿이 **승인 완료** 상태인가 (승인 전이면 발송이 안 되므로 QA 자체가 막힌다)
- [ ] 테스트 이벤트가 **실제 청춘건배 신청자에게 보이지 않는지** 확인 (비공개 또는 별도 계정)
- [ ] 참여자 전원에게 "테스트 알림톡이 갈 것"이라고 미리 공지

> ⚠️ **배포 후 QA는 실서비스다.** 알림톡이 실제로 발송되고 비용이 나간다.
> 반드시 팀원 번호로만 진행하고, 외부 번호를 절대 넣지 않는다.

### 리허설 행사 설정 (청춘건배와 같은 구조, 규모만 축소)

| 설정 | 값 | 청춘건배와 다른 점 |
|---|---|---|
| 참가 유형 | 졸업생(개인) / 재학생 팀(2~8명) | 동일 |
| 자리 | 18:00 · 19:00 · 20:00, **각 1팀** | 정원을 빨리 채워 마감을 보려고 축소 |
| 팀원 동의받기 | 켬 | 동일 |
| 동의 마감 | **1시간** | 마감 경과를 당일에 보려고 단축 |
| 신청폼 | 이름 · 전화번호 · 이메일 · 학과/학번 · 소속 | 동일 |
| 추가 질문 | 카드뉴스 동의(객관식) + 프로필 사진(파일 업로드) | 동일 |
| 로그인 사용자만 신청 가능 | 켬 | 동일 — 신청하면 총동문회에 자동 가입된다 |
| 현장 체크인 | 켬 | 동일 |

## 1. 이벤트 만들기 — 주최측

- [ ] 이벤트를 만들고 **참가 유형 나눠서 받기**를 켠다
- [ ] 졸업생(개인) / 재학생 팀(2~8명) 두 유형을 만든다
- [ ] 유형 목록에 이름과 켜 둔 설정이 맞게 표시된다 (`개인 | 참석자 공개`, `팀 2~8명 | 자리 배정 | 팀원 동의`)
- [ ] 재학생 팀 상세에서 자리 3개를 만들고 각 1팀으로 정한다
- [ ] **팀원 동의받기**를 켜고, 동의 문구를 청춘건배와 같은 내용으로 적는다
- [ ] 동의받기를 켰을 때 **팀원 전화번호가 필수로 잠기고 선택 버튼이 사라지는지** 확인
- [ ] 유형별로 신청폼을 다르게 구성한다 (졸업생에만 카드뉴스 동의 + 프로필 사진)
- [ ] 이벤트 안내에 카드뉴스 이미지를 캐러셀로 올린다 (2장 이상)
- [ ] 이벤트 설정에서 **로그인 사용자만 신청 가능**을 켠다
- [ ] 현장 체크인을 켜고 **발급 단위**를 정한다
- [ ] 발행한다

**확인 포인트**

- [ ] 발행 직후 이벤트 페이지가 열리고, 작성한 내용이 **빠짐없이 그대로** 보인다
- [ ] 캐러셀이 좌우로 넘어가고 페이지네이션 점이 맞게 움직인다
- [ ] 작성 화면에서 켠 설정만 이벤트 페이지에 나온다 (끈 것이 새어 나오지 않는다)
- [ ] 발행 후 **이벤트를 수정**했을 때 이미 들어온 신청에 문제가 없다

## 2. 로그인과 커뮤니티 자동 가입

**로그인 사용자만 신청 가능**을 켜고 행사를 여는 방식이다. 이 이벤트에 신청하면 **총동문회 커뮤니티에 자동으로 가입**된다.
신청자가 스스로 가입 버튼을 누르지 않는데 회원이 되는 것이므로, 되는지 안 되는지보다 **누가 언제 가입되는지**를 정확히 봐야 한다.

### 2-1. 로그인 없이는 신청할 수 없다

- [ ] 로그아웃 상태로 이벤트 페이지를 연다 — 페이지 자체는 보인다
- [ ] 신청 버튼을 누르면 **로그인 안내 모달**이 뜬다 (`신청하려면 로그인이 필요해요`)
- [ ] 모달을 닫으면 이벤트 페이지로 돌아오고, 신청은 진행되지 않는다
- [ ] 카카오 · 구글 · 이메일 **세 가지 방법 모두** 로그인이 된다
- [ ] 로그인을 마치면 **누르려던 신청 화면으로 그대로 이어진다** (처음부터 다시 하지 않는다)

### 2-2. 비회원이 신청하면 자동으로 가입된다

커뮤니티에 가입한 적 없는 계정으로 진행한다.

- [ ] 신청을 마치면 총동문회 **회원 목록에 그 사람이 새로 들어와 있다**
- [ ] 가입 시점이 언제인지 확인한다 — **신청 제출 시점**인지, 팀이 **확정된 시점**인지
- [ ] 본인 화면(마이페이지 등)에서도 총동문회 회원으로 보인다
- [ ] 가입 환영 알림톡이나 메일이 따로 나가는지 확인 — 나간다면 신청 알림톡과 겹치지 않는지

### 2-3. 이미 회원이면 중복으로 가입되지 않는다

- [ ] 기존 회원 계정으로 신청한다
- [ ] 회원 목록에 **같은 사람이 두 줄로 늘지 않는다**
- [ ] 기존 가입일이 신청일로 덮어써지지 않는다

### 2-4. 팀원은 어떻게 되는가 (가장 중요)

이번 행사는 **대표자가 신청하고 팀원은 링크로 동의만 한다.** 팀원은 로그인을 하지 않는다.
그래서 "신청하면 자동 가입"이 팀원에게도 적용되는지가 이 행사에서 가장 애매한 지점이다.

- [ ] 팀원이 동의를 마친 뒤, 그 팀원이 **회원 목록에 들어오는지** 확인
- [ ] 들어온다면 어떤 정보로 가입되는지 확인 (이름·전화번호만? 계정 없이도 회원이 되나?)
- [ ] 들어오지 않는다면, 팀원은 회원이 아닌 채로 행사에만 참석하는 것이 맞는지 확인
- [ ] 동의 문구(`총동문회 소식·행사 안내를 받는 데 동의합니다`)가 **가입까지 포함하는 내용인지** 확인

> **이 항목은 확인이 아니라 결정이 필요할 수 있다.**
> 이번 행사의 목적이 팀원 개개인에게 알림 수신 동의를 받는 것이므로, 동의한 팀원이 회원이 되지 않으면
> 정작 소식을 보낼 대상이 대표자뿐이 된다. 실제 동작을 보고 팀에서 정한다.

### 2-5. 자동 가입이 적용되지 않는 경로

로그인을 거치지 않고 명단에 들어오는 길이 몇 군데 있다. 각각 어떻게 되는지 본다.

- [ ] **현장 신청 등록** — 스태프가 당일 현장에서 등록한 사람 (9절)
- [ ] **호스트가 미리 등록한 참석자** — 주최측이 신청 전에 넣어 둔 사람
- [ ] 위 두 경우가 회원이 되는지 / 안 되는지, 그리고 그게 의도한 동작인지 확인

### 2-6. 신청을 취소하면

- [ ] 신청을 취소해도 **커뮤니티 회원 자격은 유지되는지** 확인
- [ ] 신청이 실패(6절)해도 회원 자격이 유지되는지 확인
- [ ] 유지된다면, 취소한 사람에게 그 사실이 안내되는지 확인 → 정책 확인 필요

### 2-7. 가입 사실을 신청자가 알 수 있는가

자동 가입은 사용자가 누르지 않은 동작이므로, 모르는 사이 회원이 되는 상황을 만들지 않아야 한다.

- [ ] 신청 화면이나 로그인 모달에 **가입된다는 사실이 보이는지** 확인
- [ ] 보이지 않는다면 어디에 어떻게 넣을지 정한다 → 문구 결정 필요
- [ ] 가입 후 커뮤니티의 **다른 알림이 오기 시작하는지** 확인 (행사와 무관한 알림이 갑자기 가면 안 된다)

## 3. 개인 신청 — 졸업생

가장 단순한 경로부터 확인한다.

- [ ] 졸업생으로 신청한다 (이름·전화번호·이메일·학과/학번·소속)
- [ ] 카드뉴스 동의에 **예**를 고르고 프로필 사진을 올린다
- [ ] 필수 항목을 비우고 제출하면 **어디가 비었는지** 알려준다
- [ ] 제출하면 신청 완료 화면이 뜨고 **QR이 발급**된다
- [ ] **신청 완료 알림톡**이 온다
- [ ] 화면을 나갔다가 다시 들어와도 QR을 다시 볼 수 있다
- [ ] 신청을 취소하면 취소되고, QR이 더 이상 유효하지 않다
- [ ] 취소 후 **같은 번호로 다시 신청**할 수 있다

**파일 업로드**

- [ ] 사진을 올리면 미리보기가 뜨고, 다시 고를 수 있다
- [ ] 아주 큰 파일(10MB 이상)을 올리면 어떻게 되는지 확인 — 막든 통과시키든 **말없이 실패하지 않아야** 한다
- [ ] 사진이 아닌 파일(PDF·zip)을 올렸을 때의 동작 확인
- [ ] 올린 사진을 **주최측이 실제로 내려받을 수 있는지** 확인 (카드뉴스 제작에 써야 한다)

## 4. 팀 신청과 동의 — 이번 행사의 핵심

**여기가 가장 중요하다.** 대표자가 대신 동의하지 못한다는 것이 이 행사의 목적이므로, 이 절은 실제 사람 여러 명이 각자 휴대폰으로 진행한다.

### 4-1. 대표자가 신청

- [ ] 재학생 팀으로 신청한다 (팀 이름 + 팀원 3명, 각자 다른 실제 번호)
- [ ] **참석 가능한 자리를 2개 이상** 고른다
- [ ] 제출하면 "동의 대기" 상태가 되고, **아직 자리가 배정되지 않았다**
- [ ] 대표자에게 **현황을 확인하라는 알림톡**이 온다
- [ ] 대표자 현황 화면에서 `1 / 3명`, 마감까지 남은 시간이 보인다

### 4-2. 팀원이 각자 동의

- [ ] 팀원 전원에게 **각자 다른 링크로** 동의 알림톡이 온다
- [ ] 팀원 A가 링크를 열면 **본인 이름·정보**가 보인다 (다른 팀원 것이 아니다)
- [ ] 동의 문구가 주최측이 작성한 그대로 보인다
- [ ] 동의를 누르면 완료되고, 대표자 화면의 숫자가 올라간다
- [ ] **이미 동의한 링크를 다시 열면** 동의 완료 상태로 보인다 (중복 동의가 되지 않는다)
- [ ] 팀원 B의 링크를 팀원 A의 휴대폰에서 열어도 **B의 정보**가 보인다 — 즉 링크만 있으면 열린다는 뜻이므로, 이게 의도한 동작인지 팀에서 확인 필요
- [ ] 마지막 팀원이 동의하는 **순간** 신청이 확정되고 자리가 배정된다
- [ ] 팀 전원에게 확정 알림톡과 QR이 간다

### 4-3. 대표자가 팀원을 제외

새 팀으로 다시 신청해서 확인한다.

- [ ] 팀원 1명이 응답하지 않는 상태에서 대표자가 **제외**를 누른다
- [ ] 제외하면 남은 인원만으로 **바로 확정**된다
- [ ] 제외된 사람에게 더 이상 알림톡이 가지 않는다
- [ ] 제외된 사람의 동의 링크를 열면 어떻게 되는지 확인
- [ ] 제외된 사람이 **엑셀 명단과 체크인 명단에 나오지 않는다**
- [ ] 팀원을 제외해서 **최소 인원 아래로** 떨어지는 경우는 6절에서 따로 확인한다

## 5. 자리 배정과 마감

자리를 각 1팀으로 잡아 두었으므로 세 팀이면 정원이 찬다.

- [ ] 팀 1이 18:00·19:00을 고르고 전원 동의 → 어느 자리에 배정되는지 확인
- [ ] 팀 2가 같은 자리를 고르고 전원 동의 → 남은 자리로 배정된다
- [ ] 팀 3이 **이미 다 찬 자리만** 골라 신청하려 하면 그 자리가 **마감으로 표시되어 고를 수 없다**
- [ ] 고른 자리가 신청 중에 마감되면 어떻게 되는지 확인 (신청 화면을 열어 둔 채 다른 팀이 먼저 채우는 상황)
- [ ] 전원 동의를 마쳤는데 **고른 자리가 모두 차 버린 경우** 어떻게 되는지 확인 → 정책 확인 필요

> **동시 확정 확인 (꼭 해볼 것)**
> 자리 1개만 남긴 상태에서, 두 팀의 마지막 팀원이 **거의 동시에** 동의를 누른다.
> - [ ] 한 팀만 배정되고 다른 팀은 적절히 처리된다
> - [ ] **두 팀이 모두 배정되어 정원을 넘지 않는다**

### 동의 마감 경과

동의 마감을 1시간으로 잡았으므로 한 팀은 일부러 방치한다.

- [ ] 마감 시각이 지나면 그 팀이 어떻게 되는지 확인
- [ ] 마감 후 팀원이 동의 링크를 열면 어떻게 되는지 확인
- [ ] 대표자에게 실패 알림톡이 가는지 확인 (6절 케이스 1-2와 같은 건이다)

## 6. 신청 실패

팀이 최소 인원을 못 채워 취소되는 경우다. **대표자가 그 순간 화면을 보고 있는지**에 따라 처리가 갈린다.

| | 언제 | 알림톡 | 화면 |
|---|---|---|---|
| **케이스 A** | 대표자가 현황 화면에서 팀원을 **제외**해 미달 | **안 보낸다** (방금 본인이 한 행동) | 그 자리에서 바로 `신청 실패` |
| **케이스 B** | **거절 · 미응답 · 시간 초과**로 미달 | 대표자에게 **기존 현황 알림톡**을 결과 필드만 `신청 실패`로 바꿔 발송 | 알림톡의 "자세히 보기"로 들어가면 `신청 실패` |

두 경우 모두 팀 상태는 `신청 실패`가 되고, 실패한 팀은 다시 신청할 수 있다.

### 테스트 준비

- [ ] 이벤트 만들기 → 재학생 팀 상세에서 **한 팀에 2~8명**으로 둔다 (최소 2명 → 3인 팀에서 한 명만 빠져도 미달을 볼 수 있다)
- [ ] 동의 마감은 0절에서 정한 **1시간** 그대로 둔다 (시간 초과를 당일에 봐야 한다)
- [ ] 그룹 3에서는 최소 인원을 3명·4명으로 바꿔 이벤트를 다시 만든다

**어느 화면에서 누르는지**

| 동작 | 위치 |
|---|---|
| 거절 | 팀원 동의 화면 맨 아래 **참석 어려워요** |
| 팀장 제외 | 대표자 현황 화면에서 팀원 옆 **제외** |
| 실패 화면 | [event-fail.html](https://connectia-design.vercel.app/prototypes/event-timeslot-0828/event-fail.html) — 사유별로 `?reason=reject / noreply / timeout / exclude` |

> **자리 확인 방법** — 동의 대기 중인 팀은 **자리를 잡지 않는다.** 전원 동의로 확정된 팀만 자리를 차지한다.
> 그러므로 실패해도 자리별 현황(`18:00 1/1`) 숫자가 **변하지 않아야** 정상이다.
> 대기 중인 팀 때문에 숫자가 올라가 있다면 그것이 버그다.

### 그룹 1 — 팀원 응답으로 인한 미달 (케이스 B)

**1-1 · 팀원이 거절해서 미달**

재현: 3인 팀(대표자 + 팀원 2명)으로 신청 → 팀원이 각자 동의 링크를 열어 **참석 어려워요**를 눌러, 남은 인원이 최소 2명 아래로 떨어지게 한다.

- [ ] 거절한 팀원 옆에 **거절** 뱃지가 뜬다
- [ ] 팀 상태가 `신청 실패`가 된다 (`동의 대기 0/0`이 아니다)
- [ ] 대표자에게 실패 알림톡이 온다 — **새 템플릿이 아니라** 기존 현황 알림톡의 결과 필드가 `신청 실패`로 바뀐 것이다
- [ ] 알림톡의 **자세히 보기**로 들어가면 실패 화면이 열린다
- [ ] 자리별 현황 숫자가 변하지 않는다 (위 박스 참고)

**1-2 · 팀원이 응답을 안 해서 시간 초과**

재현: 팀 신청 후 팀원이 아무 응답도 하지 않은 채 **동의 마감 1시간**이 지나게 둔다.

- [ ] 마감 시각이 지나면 팀 상태가 `신청 실패`가 된다
- [ ] 실패 사유가 **시간 초과**로 구분되어 보인다 (거절과 다른 사유로 표시)
- [ ] 대표자에게 실패 알림톡이 온다
- [ ] 자리별 현황 숫자가 변하지 않는다

**1-3 · 거절과 미응답이 섞였을 때**

재현: 한 명은 **참석 어려워요**, 다른 한 명은 응답 없이 마감 경과.

- [ ] 팀원 목록에서 **거절**과 **미응답**이 서로 다르게 표시된다
- [ ] 최종 상태가 `신청 실패`다
- [ ] 실패 사유가 둘 중 무엇으로 기록되는지 확인 → 표기 규칙 확인 필요

### 그룹 2 — 팀장의 제외로 인한 미달 (케이스 A)

**2-1 · 팀장이 팀원을 제외해서 미달**

재현: 3인 팀에서 대표자가 현황 화면의 **제외**를 눌러 남은 인원이 최소 아래로 떨어지게 한다.

- [ ] 제외를 누른 **그 자리에서 바로** 화면이 `신청 실패`로 바뀐다
- [ ] **알림톡이 오지 않는다** — 방금 본인이 한 행동이라 보내지 않는 것이 정책이다
- [ ] 자리별 현황 숫자가 변하지 않는다

**2-2 · 이미 동의한 팀원을 제외**

재현: 팀원이 동의를 마친 상태에서 대표자가 그 팀원을 제외해 미달을 만든다.

- [ ] 동의를 마친 팀원을 뺐을 때도 `신청 실패`가 된다
- [ ] 그 팀원이 남긴 **동의 기록 자체는 남아 있는지** 확인 — 이번 행사는 알림 수신 동의를 받는 것이 목적이라 중요하다
- [ ] 제외된 사람에게 취소 알림이 가는지 확인 → 정책 확인 필요

---

### 그룹 3 — 경계값

**3-1 · 정확히 경계에서 실패가 발동하는지**

재현: 최소 2명 설정에서 **2명 → 1명**으로 떨어지는 순간.

- [ ] 2명일 때는 실패가 아니고, 1명이 되는 순간 실패가 된다
- [ ] **0명이 되어야 실패하는 오류**가 없다

**3-2 · 최소 인원을 바꿔도 임계점이 따라가는지**

재현: 최소 인원을 **3명**, **4명**으로 바꿔 이벤트를 다시 만들고 같은 절차를 반복한다.

- [ ] 최소 3명 → 3명은 정상, 2명이 되는 순간 실패
- [ ] 최소 4명 → 4명은 정상, 3명이 되는 순간 실패
- [ ] 실패 화면의 `동의 n / m명 · 최소 N명` 표시가 설정값과 맞다

---

### 그룹 4 — 실패 후 재신청

**4-1 · 재신청도 전원이 다시 동의하는지 (꼭 확인)**

재현: 실패 화면에서 **다시 신청하기** → 재신청을 끝까지 진행한다.

- [ ] 재신청도 **팀원 전원 동의 절차**를 거친다
- [ ] 동의 요청 알림톡이 팀원 전원에게 **다시** 발송된다
- [ ] **동의 없이 바로 확정되지 않는다** — 이전에 문제가 났던 지점이므로 반드시 밟는다

**4-2 · 재신청 화면의 초기 상태**

재현: **다시 신청하기**를 눌러 들어간 신청 화면을 본다.

- [ ] 팀 정보가 채워져 있는지 / 빈 화면인지가 정한 방식과 맞다
- [ ] 거절했던 팀원이 목록에 남아 있는지, 빠져 있는지 확인 → 정책 확인 필요

**4-3 · 상태별 버튼이 맞는지 (회귀 확인)**

재현: 동의 대기 중 · 확정 · 실패 세 상태를 각각 만들어 이벤트 페이지의 버튼을 본다.

- [ ] 동의 대기 중 → **동의 현황 확인**
- [ ] 실패 → **다시 신청하기**
- [ ] 확정 → 재신청 버튼이 뜨지 않는다
- [ ] 화면을 나갔다 다시 들어와도 버튼이 그대로다

---

### 그룹 5 — 실패가 아닌데 실패로 처리되지 않는지 (반대 검증)

**5-1 · 정상 확정이 실패로 빠지지 않는지**

재현: 팀원 전원이 정상 동의한다.

- [ ] `신청 실패`로 잘못 빠지지 않고 정상 확정된다
- [ ] 실패 알림톡이 잘못 나가지 않는다

**5-2 · 최소 인원을 딱 채웠을 때**

재현: 최소 2명 설정에서 정확히 2명만 동의를 마친다.

- [ ] 미달로 오판하지 않고 확정된다
- [ ] 자리가 정상 배정되고 QR이 발급된다

---

## 7. 운영자 현황 — 주최측

- [ ] 신청자 리스트에서 **자리별 현황**이 실제 배정과 맞다 (`18:00 1/1 · 19:00 1/1 · 20:00 0/1`)
- [ ] 정원이 찬 자리의 표시가 다르게 보인다
- [ ] 확정된 팀은 배정된 자리가, 대기 중인 팀은 `동의 대기 n/m`이 보인다
- [ ] 팀을 열면 팀원 전원과 각자의 답변이 보인다
- [ ] 졸업생 / 재학생 팀 탭 전환이 맞게 걸러진다
- [ ] 총 신청 인원 수가 실제와 맞다 (팀은 팀원 수만큼 세는지 확인)

**자리 옮기기**

- [ ] 확정된 팀의 자리를 눌러 다른 자리로 옮긴다
- [ ] **정원이 찬 자리로도** 옮길 수 있다 (예외 허용이 의도)
- [ ] 옮긴 뒤 자리별 현황 숫자가 바로 맞게 바뀐다
- [ ] 정원을 넘긴 자리가 눈에 띄게 표시된다
- [ ] 자리를 옮기면 참가자에게 알림이 가는지 확인 → **정책 확인 필요. 안 가면 참가자는 바뀐 걸 모른다**

## 8. 엑셀 내보내기 — 명찰 제작

명찰을 실제로 만들 수 있는지가 목표다. 파일만 열어 보고 끝내지 말고 **캔바까지 넣어본다.**

- [ ] 졸업생만 / 재학생 팀만 / 둘 다 각각 내보내 본다
- [ ] 유형을 고르면 선택 표시(체크)가 눈에 보인다
- [ ] **한 사람씩 / 신청 건별** 두 가지를 모두 내보낸다
- [ ] 항목을 3~4개만 골라 내보냈을 때 그 열만 나온다
- [ ] 졸업생만 골랐을 때 팀에만 있는 항목(팀명·대표 여부)이 목록에서 빠진다
- [ ] 팀을 "한 사람씩"으로 내보내면 **팀원 수만큼 줄이 나온다**
- [ ] 파일을 엑셀·구글시트에서 열었을 때 **한글이 깨지지 않는다**
- [ ] 제외된 팀원, 취소한 신청자가 명단에 없다
- [ ] 아직 동의 대기 중인 팀이 명단에 어떻게 나오는지 확인
- [ ] **내려받은 파일을 캔바 대량 제작에 실제로 넣어 명찰 3장을 만들어 본다**

## 9. 당일 현장 — 체크인

- [ ] 스태프에게 체크인 전용 링크를 보낸다
- [ ] 스태프 화면에서 **참가자 연락처가 보이지 않는다**
- [ ] 참가자의 QR을 스캔하면 **누르지 않아도 바로** 입장 처리된다
- [ ] 같은 QR을 다시 스캔하면 **이미 입장**이라고 알려준다
- [ ] 취소된 신청의 QR을 스캔하면 입장이 막힌다
- [ ] 명단 탭에서 이름으로 찾아 입장 처리한다
- [ ] 재학생 팀은 **모두 입장** 한 번으로 팀 전체가 처리된다
- [ ] 자리별 칩(`18:00 1/1`)이 실제 입장 수와 맞게 올라간다
- [ ] 미입장 / 전체 필터가 맞게 걸러진다
- [ ] **현장 신청 등록**으로 그 자리에서 등록하고 입장까지 처리한다
- [ ] 두 사람이 **동시에** 같은 참가자를 입장 처리해도 숫자가 어긋나지 않는다
- [ ] 스캔 화면에서 카메라 권한을 거부했을 때 안내가 나온다

> **현장 조건에서 확인** — 행사장은 인터넷이 불안정할 수 있다.
> - [ ] 네트워크를 껐다 켜는 중에 스캔하면 어떻게 되는지 확인
> - [ ] 입장 처리가 실패했을 때 **성공한 것처럼 보이지 않는다**

## 10. 알림톡 전수 확인

QA를 진행하며 받은 알림톡을 모아 한 번에 본다.

| # | 언제 | 받는 사람 | 확인 |
|---|---|---|---|
| 1 | 팀 신청 직후 | 팀원 전원 | [ ] 도착 [ ] 문구 [ ] 링크 |
| 2 | 팀 신청 직후 | 대표자 | [ ] 도착 [ ] 문구 [ ] 링크 |
| 3 | 전원 동의 완료 | 팀 전원 | [ ] 도착 [ ] 문구 [ ] 링크 |
| 4 | 개인 신청 완료 | 신청자 | [ ] 도착 [ ] 문구 [ ] 링크 |
| 5 | 거절·미응답·시간 초과로 실패 | 대표자 | [ ] 도착 [ ] 결과 필드가 `신청 실패` [ ] 링크 |
| 6 | 대표자가 제외해서 실패 | — | [ ] **오지 않아야 한다** (케이스 A) |
| 7 | 행사 전날 리마인드 | 참가자 전원 | **미정** — 넣을지 여부 결정 필요 |

**공통 확인**

- [ ] 발신 이름이 **서울시립대학교 총동문회**로 나온다
- [ ] 행사명·날짜·시간이 실제 설정과 맞다
- [ ] 링크를 눌렀을 때 **로그인 없이** 해당 화면이 바로 열린다
- [ ] 카카오톡이 없는 번호에는 문자로 대체 발송되는지 확인
- [ ] 같은 알림톡이 두 번 오지 않는다
- [ ] 실패 알림톡 때문에 **새 템플릿이 늘지 않았다** — 5번은 2번과 같은 템플릿에서 결과 필드만 바뀐 것이다

참가자는 대부분 알림톡 링크를 **카카오톡 안에서** 연다. 이 환경을 반드시 포함한다.

- [ ] iPhone Safari
- [ ] Android Chrome
- [ ] **카카오톡 인앱 브라우저** (동의·신청·QR 모두)
- [ ] PC 브라우저 (주최측 화면 위주)
- [ ] 작은 화면(320px 폭)에서 글자가 잘리거나 가로 스크롤이 생기지 않는다
- [ ] 휴대폰 글자 크기를 크게 설정한 상태에서 버튼이 눌린다

## 12. 마무리

- [ ] 테스트 이벤트를 삭제하거나 비공개로 돌린다
- [ ] 테스트로 올린 프로필 사진 등 개인정보를 지운다
- [ ] 자동 가입으로 **커뮤니티 회원이 된 테스트 계정을 정리**한다 (2절에서 늘어난 회원)
- [ ] QA 중 나온 문제를 **화면 캡처 + 재현 순서**와 함께 정리한다
- [ ] 정책을 정해야 하는 항목을 모아 팀에 공유한다

### 이번 QA에서 결정해야 하는 것

QA를 하며 실제 동작을 보고 팀이 정할 것들. 코드 문제가 아니라 **아직 안 정한 것**이다.

1. 전원 동의했는데 고른 자리가 모두 차 버린 경우의 처리
2. 주최측이 자리를 옮겼을 때 참가자에게 알릴지
3. 행사 전날 리마인드 알림톡을 넣을지
4. 거절·미응답이 섞였을 때 실패 사유를 무엇으로 적을지 (6절 1-3)
5. 제외된 팀원에게 취소 알림을 보낼지 (6절 2-2)
6. 재신청 화면에서 거절했던 팀원을 남길지 뺄지 (6절 4-2)
7. **동의한 팀원도 커뮤니티 회원이 되게 할지** (2절 2-4) — 이번 행사의 목적과 직결된다
