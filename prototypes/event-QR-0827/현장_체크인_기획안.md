# QR 발급 · 현장 체크인 기획안

청춘건배 행사 적용 기준 · v1

---

## 1. 목적

오프라인 행사에서 신청자를 현장에서 확인하고 입장 처리하는 기능.

현재는 사전신청을 받아도 현장에서는 명단을 출력하거나 스프레드시트를 스크롤하며 구두로 확인해야 한다. 이 과정에서 줄이 밀리고, 실제로는 대조가 제대로 되지 않으며, 인원이 추가로 투입된다.

**해결하려는 것**

- 입장 확인 시간 단축
- 결제(후원금·참가비) 여부를 현장에서 즉시 확인
- 참석 여부가 데이터로 남아 정산·차기 행사에 활용

**청춘건배에서의 용도** — 재학생·졸업생 입장 확인. 공연 행사 대응에 앞서 실제 행사에서 먼저 검증하는 목적도 있다.

## 2. 범위

### 포함

| 구분 | 내용 |
|---|---|
| 설정 | 이벤트 작성 시 QR 사용 여부, 발급 시점, 발급 단위 |
| 발급 | 신청 완료 화면 노출 + 알림톡 발송 |
| 스캔 | 카메라로 QR 인식 → 입장 처리 |
| 명단 | 압축 목록 · 검색 · 미입장 필터 · 수동 체크 |
| 예외 | 현장 신청 등록, 입장 취소, 중복 스캔 처리 |
| 권한 | 스태프용 체크인 전용 링크 |
| 현황 | 실시간 입장 집계 |

### 제외

| 항목 | 사유 |
|---|---|
| PC 전용 레이아웃 | 이번 행사 규모에서 불필요. 대행사 니즈 확인 후 판단 |
| 좌석 지정 | 해당 없음 |
| 퇴장 체크 | 필요성 미확인 |
| 오프라인(네트워크 단절) 모드 | v1 범위 초과. 단, 실패 시 재시도 UI는 필요 |

## 3. 이벤트 작성 화면 — 설정

작성 화면에 아래 블록을 추가한다.

```
현장 체크인
  [ ] QR 발급 및 현장 체크인 사용

  ── 켜면 나타남 ──
  발급 시점    ( ) 신청 즉시    (•) 결제 완료 후
  발급 단위    (•) 신청 건당    ( ) 참가자 1인당
```

**조건부 노출**

- `발급 시점` — 참가비를 설정한 유형이 있을 때만 표시. 무료 이벤트는 신청 즉시로 고정
- `발급 단위` — 팀 단위 신청 유형이 있을 때만 표시

**온·오프라인 여부는 별도로 묻지 않는다.** 온라인 행사는 이 토글을 켜지 않으면 되므로 설정 항목을 하나 줄인다.

**사후 활성화 허용** — 신청을 받기 시작한 뒤에 켜는 경우, 기존 신청자 전원에게 QR을 일괄 재발송한다. 주최자가 설정을 누락하는 경우가 발생하므로 막지 않는다.

## 4. QR 발급

### 발급 시점

| 조건 | 시점 |
|---|---|
| 무료 유형 | 신청 완료 즉시 |
| 참가비 유형 | 결제 완료 후 |
| 현장 수납 | 현장에서 수동 입장 처리 (QR 없음) |

### 전달 경로

1. **신청 완료 화면에 즉시 노출** — 캡처 유도
2. **알림톡 발송** — 전화번호만 있으면 발송 가능하므로 로그인 불필요
3. **행사 전날 리마인드 알림톡에 재첨부** — 노쇼 감소 목적

### QR 내용

신청 고유 코드만 담는다. 개인정보는 포함하지 않으며, 스캔 시 서버에서 조회한다.

### 팀 신청의 경우

`발급 단위` 설정에 따라 갈린다.

- **신청 건당** — 대표자에게 QR 1개. 팀 전체를 한 번에 입장 처리
- **참가자 1인당** — 연락처가 입력된 팀원에게 개별 발송. 연락처가 없는 팀원은 대표자 QR에 포함

---

## 5. 진입점

이벤트 페이지 상단, 기존 `신청자 보기` 옆에 `체크인` 버튼을 추가한다. 별도 관리자 메뉴를 만들지 않는다.

**노출 조건**

- QR 설정을 켠 이벤트
- 주최자 또는 체크인 링크 보유자
- 행사 시작 3시간 전 ~ 종료 3시간 후 (신청 기간 중 오조작 방지)

버튼을 누르면 전체 화면 모드로 전환된다.

---

## 6. 체크인 화면

상단에 `스캔` / `명단` 두 개 탭. 기본은 `스캔`.

헤더에 항상 `나가기`와 `입장 N / 신청 N`을 표시한다.

### 6-1. 스캔 탭

**기본 상태** — 카메라 뷰 + 안내 문구 + `QR이 없어요 · 이름으로 찾기` 버튼(명단 탭으로 이동)

**스캔 결과**

| 케이스 | 표시 | 액션 |
|---|---|---|
| 정상 | 이름 · 유형 · 소속 · 결제 완료 | `입장 처리` |
| 미결제 | 이름 · **미결제 · 현장 수납 필요** 경고 | `수납 확인 후 입장` |
| 중복 | 이름 · **이미 입장 완료 (시각)** | 액션 없음, 자동 복귀 |
| 다른 행사 QR | **이 행사의 QR이 아닙니다** | 액션 없음 |
| 취소된 신청 | **취소된 신청입니다** | 액션 없음 |

**동선 원칙**

- 입장 처리 후 **자동으로 카메라 복귀**. 확인 팝업 없음
- 결과 표시는 1~2초 유지 후 자동 전환, 또는 즉시 다음 스캔 가능
- 결과는 색으로 즉시 구분 (정상 초록 / 경고 빨강 / 중복 노랑)

### 6-2. 명단 탭

**상단** — 검색창(이름 · 전화번호 뒷자리) + 필터 칩

```
[미입장 9]  [전체 21]
```

**기본 필터는 미입장.** 처리한 사람이 목록에서 사라져 남은 인원이 줄어드는 것이 보이도록 한다.

**목록 행 구성** — 한 화면에 15행 이상 들어가는 밀도

```
이름   보조정보(학번·학과 또는 팀 인원)   [입장]
```

- 미결제자는 이름 옆에 `미결제` 표시
- 입장 완료자는 버튼 대신 `입장 18:12` 텍스트
- **원탭으로 입장 처리, 확인 팝업 없음**

**하단** — `현장 신청 등록` 버튼

### 6-3. 상세 화면

목록에서 이름을 탭하면 진입.

- 신청 정보 전체 (연락처, 학과, 학번, 소속, 신청 일시)
- 결제 상태
- 입장 상태 및 시각, **입장 취소** 가능
- 팀인 경우 팀원 목록 → **개별 체크 + 팀 전체 입장 처리** 둘 다 제공

> 청춘건배 재학생 팀은 팀원이 따로 도착하는 경우가 많을 것으로 예상되므로 개별 체크가 반드시 필요하다.

### 6-4. 현장 신청 등록

사전신청 없이 온 사람을 즉석에서 추가한다.

- 최소 입력만 받는다 — 이름, 전화번호, 유형
- 참가비가 있으면 `현장 수납` 체크
- 등록 즉시 입장 처리
- 명단에 `현장 등록` 표시로 구분

---

## 7. 스태프 권한

현장 입장 처리는 주최자 혼자 하지 않는다. 청춘건배도 스태프가 붙을 것으로 예상된다.

**체크인 전용 링크 방식을 채택한다.**

- 주최자가 `체크인 링크 복사` → 카톡 등으로 스태프에게 전달
- 링크 진입 시 **스캔 · 명단 탭만** 열림
- 신청자 상세 정보(연락처 등), 이벤트 설정, 정산 정보는 노출하지 않음
- 링크는 행사 종료 후 자동 만료
- 주최자가 링크를 재발급하면 기존 링크는 무효화

계정 초대 방식은 하루짜리 행사에 가입 절차가 과하므로 v1에서 제외한다.

---

## 8. 상태 정의

각 신청 건이 가지는 상태.

| 상태 | 설명 |
|---|---|
| 신청 완료 | 폼 제출 완료 |
| 결제 대기 | 참가비 유형, 결제 미완료 |
| 결제 완료 | QR 발급 조건 충족 |
| 입장 완료 | 체크인 처리됨 (시각 기록) |
| 현장 등록 | 사전신청 없이 현장에서 추가됨 |
| 취소 | 신청 취소 |

**신청자 보기 화면**에는 입장 상태를 **읽기 전용 배지**로만 표시한다. 체크 액션은 체크인 화면에만 두어 두 화면의 역할이 겹치지 않게 한다.

## 9. 예외 케이스

| 상황 | 처리 |
|---|---|
| QR을 못 찾음 · 알림톡 미확인 | 명단 탭에서 이름 검색 후 수동 체크 |
| 동명이인 | 검색 결과에 전화번호 뒷자리 함께 표시 |
| 잘못 입장 처리 | 상세 화면에서 입장 취소 |
| 캡처 화면이 흐려 인식 안 됨 | 수동 체크로 전환 |
| 네트워크 지연 | 처리 중 표시 + 실패 시 재시도 버튼. 이중 처리 방지 |
| 스태프 여러 명이 동시 처리 | 서버 기준 최초 처리만 반영, 이후는 중복으로 표시 |
| 미결제자가 현장 수납 | 수동 입장 처리 시 `현장 수납` 기록 |

## 10. 실시간 현황

체크인 화면 상단 또는 별도 영역에 표시.

- 입장 N / 신청 N
- 유형별 집계 (졸업생 12/18, 재학생 1팀/3팀)
- 현장 수납 건수, 현장 등록 인원

행사 종료 후에는 참석 명단과 노쇼 집계로 이어진다.

## 12. 이번 행사에서 측정할 것

기능 개선과 차기 영업 근거로 사용.

| 항목 | 이유 |
|---|---|
| 1인당 입장 처리 소요 시간 | 종이 명단 대비 효과 |
| QR 수동 체크 비율 | 예상보다 높으면 명단 탭이 주 화면이 됨 |
| 현장 등록 건수 | 사전신청 전환율 파악 |
| 입장 처리 투입 인원 | 인건비 절감 근거 (밴드 공연 시급 5,000원과 동일 성격) |
| 노쇼율 | 리마인드 알림톡 효과 |
| 네트워크 문제 발생 여부 | 오프라인 모드 필요성 판단 |

## 13. 오픈 이슈

| 이슈 | 내용 |
|---|---|
| 알림톡 발신 명의 | 주최자 명의 발송 가능 여부 |
| QR 인식률 | 캡처 이미지·화면 밝기에 따른 실패율 확인 필요 |
| 팀 발급 단위 기본값 | 청춘건배는 신청 건당이 자연스러우나, 팀원 개별 알림 필요 시 재검토 |
| 체크인 링크 보안 수준 | 만료 시간 외 추가 제한이 필요한지 |
