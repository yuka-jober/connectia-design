## A. 버그 (디자인 수정 전에 먼저 고쳐야 함)

프로토타입은 아래 버그가 고쳐졌다는 전제로 동작해요. 이 버그가 남아 있으면 새 흐름도 똑같이 헤매게 돼요.

### A-1. 새로고침하면 가입 대기 상태가 사라짐 — 우선순위 높음
- **재현:** 웰컴 페이지(`/krj/welcome`)에서 가입 신청 → 상단이 [가입 대기중]으로 바뀜 → 페이지 새로고침
- **현재:** 버튼이 다시 [가입하기]로 돌아감 (영상 2:55)
- **기대:** 서버에 저장된 가입 신청 상태를 읽어서 [승인 대기]로 표시. 다른 기기나 다른 화면에서 들어와도 같아야 함

### A-2. 신청 직후 이벤트 페이지가 갱신되지 않음 → 같은 이벤트 중복 신청 — 우선순위 높음
- **재현:** 이벤트 신청 완료 → [닫기] → 이벤트 페이지로 돌아감
- **현재:** "지금까지 3명" / [신청하기]가 그대로 (영상 0:28). 새로고침해야 4명 / [내 신청]으로 바뀜. 그 사이 다시 신청할 수 있어서 계정 설정 › 신청한 이벤트에 **같은 이벤트가 2건** 생김 (영상 3:35)
- **기대:**
  - 신청 완료 후 이벤트 페이지의 신청자 수와 CTA가 즉시 갱신됨
  - 서버에서 같은 계정의 같은 이벤트 중복 신청을 막음 (클라이언트 갱신과 별개로)

### A-3. 가입한 커뮤니티에 승인 대기 모임이 안 보임
- **현재:** 가입 신청 후 내 페이지 › 가입한 커뮤니티에 경륜재가 없음 (영상 3:10)
- **기대:** 승인 대기 모임도 목록에 표시하고, 상태(승인 대기 / 가입 완료)를 같이 내려줌

### A-4. 가입 폼 [신청하기]가 비활성인 이유가 안 보임 — 우선순위 낮음 (새 디자인에서 해결)
- **현재:** 개인정보 동의 체크박스가 스크롤 아래에 숨어 있어서 버튼이 왜 비활성인지 모름 (영상 1:40)
- **새 디자인:** 동의 체크박스를 하단 고정 영역의 버튼 바로 위에 둠. 버튼은 항상 활성이고, 동의하지 않고 누르면 체크박스에 에러 표시

## B. 새 흐름 구현에 필요한 것

### B-1. 가입 상태 모델
계정 × 모임마다 상태 하나: `none`(가입 전) / `pending`(승인 대기) / `member`(회원) / `rejected`(거절됨)

- 이벤트 페이지, 모임 페이지, 가입한 커뮤니티가 **모두 이 값 하나를 읽어야** 함
- 모임 설정 "가입 시 운영자 승인 필요"에 따라 신청 결과가 `pending` 또는 `member`

### B-2. 이벤트 신청 완료 → 가입 모달 노출 조건
| 가입 상태 | 신청 완료 화면 |
|---|---|
| `none` | "○○ 회원으로도 가입할까요?" 바텀시트 자동 노출 |
| `pending` | 모달 없음. 완료 화면에 "○○ · 승인 대기" 행 |
| `member` | 모달 없음. 하단에 [회원 메뉴로 가기] |
| `rejected` | 모달 없음. "○○ 다시 신청하기 ›" 행 |

- 모달에서 [다음에 할게요] → 닫기만 함. 상태 변화 없음 (다음 방문 때 진입점이 다시 보임)
- 모임이 가입을 받지 않는 설정이면 모달을 띄우지 않음

### B-3. 가입 폼 프리필
- 이벤트 신청 때 입력한 **이름·전화번호**를 가입 폼에 채움 (계정 이름이 아니라 이벤트 입력값 우선 — 영상에서 계정 이름 "이동욱"이 채워져 사용자가 "네오"로 고쳐 씀)
- 이메일은 계정 이메일로 채움
- 가입 항목 구성과 상관없이 **늘 같은 폼**. 이미 채워진 항목은 확인만 하고 제출

### B-4. 제출 후 결과
- 승인제: "가입 신청을 보냈어요" + "운영자 승인 후 회원 메뉴를 이용할 수 있어요. 승인되면 알림으로 알려드려요." + [내 모임 보기] / [닫기]
  - **승인·거절 시 알림 발송이 필요함** (이 문구가 약속하는 동작)
- 즉시 가입: "○○ 회원이 되었어요" + [회원 메뉴로 가기] / [닫기]
- [내 모임 보기] → 내 페이지 시트의 **가입한 커뮤니티 탭이 열린 상태**로 이동

### B-5. 재방문 시 화면별 표시
| 화면 | none | pending | member | rejected |
|---|---|---|---|---|
| 이벤트 페이지 하단 | 모임 상태 행 "○○ 가입하기 ›" | "○○ · 승인 대기" | "○○ 회원 메뉴 ›" | "○○ 다시 신청하기 ›" |
| 이벤트 페이지 CTA | 신청 전 [신청하기] / 신청 후 [내 신청] | 같음 | 같음 | 같음 |
| 모임 페이지 (상단 "○○에 초대받았어요" 띠) | 띠 안 [가입하기] | 띠 안 "승인 대기" 상태 표시 | 띠 없음 + 하단 탭바(홈/멤버/게시판/행사/설정) = 회원 메뉴 | 띠 안 [다시 신청하기] |
| 가입한 커뮤니티 | 없음 | "승인 대기" | "가입 완료" | 없음 |

## 확인이 필요한 정책 (기획·개발 함께)
- 거절된 사람이 다시 신청할 수 있는 횟수나 기간 제한이 있는지
- 비로그인 상태로 이벤트를 신청한 경우: 가입 모달에서 [가입하기]를 누르면 로그인을 거친 뒤 프리필된 폼으로 돌아오는지 (프로토타입은 로그인 상태만 다룸)
