# PRD — 이벤트 만들기 입력창 (사업자용)

## 0. 한 줄 요약
병원 등 사업자가 **이벤트 랜딩 페이지를 직접 만들 수 있는 입력 화면.** IT에 익숙하지 않은 사람도 막힘 없이 끝까지 채울 수 있어야 한다.

---

## 1. 배경 / 목적
- 이벤트 랜딩(고객이 보는 쪽)은 슬롯 구조로 만들어졌다 — 배치·순서는 잠겨 있고, 내용만 채우면 페이지가 조립된다. 이 입력창은 그 **빈칸을 사업자가 채우는 화면**이다.
- 사업자는 병원·소상공인이 다수이고, **IT에 익숙하지 않은 사람도 많다.**
- 목적: 입력의 어려움 때문에 이벤트를 못 만드는 일이 없게 한다. (입력이 쉬울수록 → 이벤트가 많이 만들어지고 → 리드 유입이 늘어난다)

## 2. 성공 기준
- 설명서 없이, 화면만 보고 끝까지 채울 수 있다.
- 채운 결과가 곧바로 전환되는 랜딩으로 조립된다 (사업자가 배치·디자인을 고민할 필요 없음).
- "이거 뭘 적으라는 거지?"에서 멈추는 칸이 없다.

---

## 3. 핵심 설계 원칙
- **한 스크롤 구조.** 분기가 없으므로(병원 하나, 항목 고정) 단계별 마법사로 쪼개지 않는다. 전체가 한눈에 보이고, 아무 칸이나 바로 수정 가능.
- **압도감 방어:** 상단에 진행 표시 + "필수 항목만 채우면 완성", 필수/기본값/선택을 시각적으로 구분.
- **빈 칸 대신 예시·기본값.** 모든 입력 칸에 예시 플레이스홀더. 연락 관련 항목은 빈 칸이 아니라 기본값을 미리 채워두고, 바꾸고 싶을 때만 수정.
- **자유도는 의도적으로 최소화.** 사업자가 직접 칸을 만들거나 배치를 바꾸지 못한다. 선택지는 "만들기"가 아니라 "고르기".
- **쉬운 말로.** 라벨에 마케팅/IT 용어(헤드라인 등) 쓰지 않는다. 사업자가 바로 이해하는 말로.
- **실시간 미리보기.** 채우는 대로 결과 페이지가 옆에서 조립되는 걸 보여준다.
- 디자인 토큰·컴포넌트는 프로젝트 디자인 시스템을 그대로 따른다. 임의 색·폰트 금지.

---

## 4. 입력 항목 (한 스크롤, 4개 섹션)

> 표기: ★필수 / ●기본값(수정가능) / ○선택 / 🔒고정(자동, 입력 불가)

### 섹션 1 — 기본 정보
- **이벤트 이름** ★ — 관리용, 고객에게 안 보임. 예시: "6월 라식 전액지원 이벤트"
- **신청 기간** ★ — 시작일~종료일. D-Day는 자동 계산.

### 섹션 2 — 고객에게 보이는 내용
- **썸네일 이미지** ★ — 1~5장, 4:3 권장, 캐러셀. 의료진 얼굴 권장 안내 문구.
- **이벤트 제목(혜택)** ★ — 한 줄. (※ "헤드라인" 용어 쓰지 않음) 예시: "라식·라섹 1명 전액지원". 도움말: "고객이 가장 먼저 보는 문구예요"
- **누구를 위한 건가요(대상)** ★ — 한 줄. 예시: "서울시립대 재학생·졸업생 한정"
- **자격 조건** ○ — 2~4줄. "해당하는 것만 골라주세요". 칩으로 추가.
- **이벤트 설명** ○ — 장문. 4줄 넘으면 랜딩에서 "더보기"로 접힘. 도움말: "길게 안 써도 돼요"

### 섹션 3 — 신청 폼 구성
- **관심 항목** ★ — 리드 품질의 핵심.
  - 라벨: 기본 "관심 시술", 수정 가능.
  - 선택지: 2~5개. 예시: 라식 / 라섹 / 고민 중.
  - **표현은 칩(버튼) 형태.** (기능은 단일 선택 = 기존 라디오 로직과 동일, 외관만 칩)
- 🔒 이름·연락처·약관 동의는 시스템 고정. 사업자가 못 건드림. (입력창엔 "자동 포함(수정 불가)" 안내만 표시)

### 섹션 4 — 신청 버튼 · 완료 화면
- **신청 버튼 문구** ● — 기본값 "상담 안내 신청". 수정 가능.
- **완료 화면** ● — 아래 3개는 기본값이 미리 채워져 있고, 바꾸고 싶을 때만 수정. 비워둬도 기본값으로 발행됨.
  - 완료 메시지: "곧 ○○에서 연락드릴 예정이에요"
  - 예상 연락 시점: "1영업일 이내"
  - 연락 방식: "전화 · 카카오 알림톡"

---

## 5. 시스템이 자동 처리 (입력 ❌)
입력창에는 "자동으로 들어가요"라고 안내만 표시:
- 병원명·병원 페이지 링크 (사업자 계정에서 가져옴)
- 별점·후기 수·후기 카드 (시스템 연동)
- "커넥티아 공식 이벤트" 뱃지
- "○○명 신청" 카운트
- 약관 동의 문구
- D-Day 표시

---

## 6. 범위 밖 / 미정
- ❌ **신청 폼 추가 항목 기능 — 이번 제외.** 사업자가 첫눈애안과 하나뿐이라 기본(관심 항목·이름·연락처)으로 충분. 사업자가 늘어 실제 요구가 나오면, '자유 입력'이 아니라 '준비된 선택지 켜기' 방식으로 추가 검토. (자유 입력 칸은 컴플라이언스·이탈 리스크로 지양)
- ❌ 업종 확장(한의원·글로벌)에 따른 분기 입력 — 나중. 지금은 병원 하나.
- ⚠️ **의료광고 심의번호 — 법률 검토 후 필수 여부 결정.** 의료법상 노출 의무일 수 있어, 의무면 필수 입력 칸으로 추가해야 함. (클코가 임의로 정하지 말 것)
- ❓ 후기 연동 방식, 이미지 매수 상한, 이벤트 종료 후 처리(자동 비활성/수동 종료) — 미정. 정해지면 전달.

---

## 7. 한눈 정리 (사업자가 실제로 채우는 것)
필수로 채우는 것: 이벤트 이름, 신청 기간, 썸네일, 이벤트 제목(혜택), 대상, 관심 항목.
기본값만 확인하면 되는 것: 신청 버튼 문구, 완료 화면 3종.
선택(접어둠): 자격 조건, 이벤트 설명.
자동/고정: 이름·연락처·동의·별점·뱃지·D-Day 등.
