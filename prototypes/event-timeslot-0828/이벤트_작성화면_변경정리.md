# 이벤트 작성 화면 — 변경 정리

26년 청춘건배 준비를 기준으로, **지금 서비스에 있는 이벤트 작성 화면**과 달라지는 점을 정리했습니다.
화면 확인: <https://connectia-design.vercel.app/prototypes/event-timeslot-0828/flow.html>

---

## 1. 화면에서 눈에 보이는 변화

### 이벤트 안내

| 지금 | 바뀐 뒤 |
| --- | --- |
| 제목이 `이벤트 설명`으로 고정 | 제목이 `이벤트 안내`이고, **옆의 연필을 눌러 이름을 바꿀 수 있다** |
| `설명 직접 작성` / `PDF 업로드` 두 개의 채운 버튼 | 직접 작성이 기본. `PDF로 등록`만 오른쪽에 작은 글씨 버튼으로 |

주최자가 바꾼 제목은 그대로 이벤트 페이지의 섹션 제목이 됩니다. `모집 안내`, `행사 안내`처럼 행사 성격에 맞게 부를 수 있습니다.
지금은 작성 화면은 `이벤트 설명`, 이벤트 페이지는 `이벤트 안내`로 서로 다른 이름을 쓰고 있는데, 이것도 함께 맞춰집니다.

### 신청폼 구성

| 지금 | 바뀐 뒤 |
| --- | --- |
| `자체 신청폼` / `외부 링크` 두 개의 채운 버튼이 항상 나란히 | 자체 신청폼이 기본. **고르지 않은 방식만** 오른쪽에 작은 글씨 버튼으로 |
| 받는 방식이 두 가지 | **세 가지** — 자체 신청폼 · 외부 링크 등록 · 참석여부 |
| `필수` / `선택` 버튼이 보라색 | **회색**. 색은 항목을 켜고 끄는 체크박스에만 남긴다 |

`참석여부`는 신청폼 없이 참석/불참만 받는 방식입니다. **커뮤니티에서, 참가자를 유형별로 나누지 않을 때만** 고를 수 있습니다.

### 참가 유형 (새로 생기는 개념)

참가자를 나눠 받는 기능이 들어갑니다. 청춘건배는 `졸업생`(개인 신청)과 `재학생 팀`(팀 신청)으로 나눕니다.

- 유형 목록에는 **이름과 켜 둔 설정만** 보입니다 — `팀 2~8명 | 자리 배정 | 팀원 동의`
- 카드를 누르면 **그 유형만 다루는 화면**으로 들어가고, 거기서 신청폼·자리 배정·팀원 동의·참석자 공개를 정합니다
- 유형마다 정할 수 있는 것: 신청 단위(개인/팀), 팀 인원 범위, 유형별 안내, 신청폼, 신청 방식, 자리 배정, 팀원 동의, 참석자 공개

### 참석자 사전 등록

자주 쓰는 기능이 아니라, 카드 대신 **`미리 등록할 참석자가 있나요?` 텍스트 한 줄**로 접었습니다. 이벤트 설정 바로 위에 있고, 누르면 펼쳐집니다.

### 현장 체크인 (새로 생기는 항목)

`QR 발급 및 현장 체크인` 항목이 생깁니다. 켜면 발급 단위(신청 건당 / 참가자 1인당)를 고릅니다.

## 2. 주최자가 따로 손대지 않아도 자동으로 도는 것

작성 화면이 스스로 판단해 항목을 넣고 빼거나 값을 맞춥니다. **주최자가 앞뒤가 안 맞는 설정을 만들 수 없게** 하려는 것입니다.

### 참가 유형을 켜면

| 무엇이 | 어떻게 |
| --- | --- |
| 신청폼 | `신청폼 구성` 섹션이 **통째로 사라지고**, 폼이 유형별 상세 화면 안으로 들어간다 |
| 이미 짜 둔 신청폼 | **첫 유형이 그대로 물려받는다.** 유형을 나누기 전에 만든 폼이 버려지지 않는다 |
| 신청 방식 | 자체/외부도 유형별 설정이 된다. 졸업생은 외부 링크, 재학생 팀은 자체 폼처럼 섞을 수 있다 |
| 참석여부 | 고를 수 없게 된다. 참석/불참만 받는데 유형을 나눌 이유가 없다 |
| 이벤트 페이지 | 하단 신청 버튼이 유형 개수만큼 생긴다 |

유형을 다시 끄면 신청폼이 원래 자리로 돌아옵니다.

### 신청 단위를 `팀`으로 바꾸면

- `한 팀에 O~O명` 인원 범위가 나타난다
- 신청폼이 **팀 정보 / 팀원 정보 2층**으로 바뀐다 (팀 이름·팀 사연은 1건, 이름·전화번호는 팀원마다)
- `팀원 동의받기`를 켤 수 있게 된다 (개인 유형에는 동의받을 팀원이 없다)
- 자리 수의 단위가 `명` → `팀`으로 바뀐다

### 팀원 동의받기를 켜면

- 팀원 정보의 **전화번호가 필수로 고정**된다. 동의 요청을 알림톡으로 보내야 하므로 전화번호가 전제다
- 동의 내용과 동의 마감(6/12/24/48/72시간)을 정한다
- 팀원 전원이 동의를 마치는 **순간 자리가 배정되고** 신청이 확정된다. 그전까지는 자리를 차지하지 않는다
- 알림톡이 양쪽으로 나간다 — 팀원에게는 동의 요청, 대표에게는 진행 현황

### 참석자 공개를 켜면

- 이벤트 설정의 **`신청자 목록 노출`이 자동으로 함께 켜진다.** 상위 설정이 꺼져 있으면 공개가 성립하지 않기 때문
- 공개할 항목은 **신청폼에서 실제로 받는 항목만** 고를 수 있다. 폼에서 항목을 끄면 공개 목록에서도 사라진다

반대로 `신청자 목록 노출`을 끄면, 이미 참석자 공개를 켜 둔 유형에 잠금 표시가 붙습니다.

### 외부 링크로 받기로 하면

- **유형을 나누지 않을 때** — 참가 유형 섹션이 통째로 사라지고, 신청자 수 노출도 끌 수 없게 된다. 신청을 우리가 받지 않으니 셀 수가 없다
- **유형별로 받을 때** — 그 유형에서만 자리 배정·팀원 동의·참석자 공개가 사라진다. 바꾸기 전에 **안내 모달로 한 번 확인**을 받는다

### 자리 배정을 켜면

- 자리를 여러 개 등록한다. 이름은 자유다 — `18:00`, `A 테이블`, `1부` 모두 가능
- 신청자가 **참석 가능한 자리를 여러 개** 고르면, 등록한 순서대로 훑어 남은 자리가 있는 첫 곳으로 자동 배정된다
- 정원이 찬 자리는 신청자에게 `마감`으로 보인다
- 운영자는 신청자 리스트에서 자리별 현황(정원 대비)을 보고, 자리 배지를 눌러 옮길 수 있다

### 현장 체크인을 켜면

- 팀 유형이 있을 때만 `발급 단위`를 묻는다. 개인만 있으면 둘의 결과가 같아서 물을 이유가 없다
- `신청 건당`이면 팀은 QR 한 장으로 통째로 들어온다 — 현장 화면에 `모두 입장` 버튼 하나
- `1인당`이면 팀원을 한 명씩 처리한다
- 현장 등록은 개인 유형만 가능하다. 문 앞에서 팀을 구성할 수는 없다

## 3. 커뮤니티에서만 보이는 설정

같은 작성 화면이지만, **커뮤니티에서 만든 이벤트**에는 항목이 더 나오고 순서도 다릅니다.

### 커뮤니티에서만 보이는 것

| 항목 | 왜 커뮤니티에만 |
| --- | --- |
| **커뮤니티 회원만 신청 가능** | 일반 페이지에는 회원이라는 개념이 없다 |
| **참석여부로 받기** | 이미 아는 사람들에게 참석 여부만 묻는 방식. 처음 보는 사람이 들어오는 일반 페이지에는 맞지 않는다 |

### 양쪽 다 있지만 다르게 동작하는 것

| 항목 | 일반 페이지 | 커뮤니티 |
| --- | --- | --- |
| 참석자 사전 등록 | 기본으로 접혀 있다 (거의 안 쓴다) | 펼친 채로 시작한다 |
| 신청폼의 이메일 | 기본으로 켜짐 | 기본으로 꺼짐 (이미 아는 사람들이라 다시 받을 이유가 적다) |
| 일정 | `신청 기간`을 펼친 채로 시작 | `행사 일정`을 펼친 채로 시작 |
| 섹션 순서 | 일정 → 참가 유형 → 신청폼 → 참석자 → 체크인 → 설정 | 일정 → **참석자** → 참가 유형 → 신청폼 → 체크인 → 설정 |

### 양쪽 다 같은 것

대표 사진, 이벤트 이름, 이벤트 안내, 참가 유형, 신청폼, 자리 배정, 팀원 동의, 참석자 공개, 현장 체크인, 그리고 이벤트 설정의 나머지(신청 버튼 문구·리뷰 노출·댓글 허용·신청자 수 노출·신청자 목록 노출·로그인 사용자만 신청 가능·AI 학습).

## 4. 아직 정하지 못한 것

- **참석여부로 받을 때 이벤트 페이지의 모습.** 지금은 하단 버튼이 `참석해요` 하나로 바뀌는 수준까지만 만들었습니다. 불참을 따로 받을지, 참석자 명단을 어떻게 보여줄지는 정하지 않았습니다.
- **자리 배정을 팀 유형이 둘 이상일 때.** 발급 단위를 유형마다 다르게 줘야 하는 경우가 실제로 있을지 확인이 필요합니다.
