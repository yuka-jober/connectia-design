## 1. 템플릿 전환을 없앴다

처음에는 "기본형 ↔ 카드형 전환"을 어디에 둘지가 문제였다. 상단에 알약을 하나 더 두거나,
배경 흰색 토글로 처리하는 안이 있었다.

**결론은 전환이라는 개념 자체를 두지 않는 것.** 두 템플릿의 차이는 사실 둘뿐이었다.

| 차이 | 어디서 고르나 |
|---|---|
| 프로필 머리 생김새 | 디자인 > 프로필 > **레이아웃** |
| 섹션이 흰 면에 올라가는지 | 디자인 > 블록 > **카드 면** |

이 둘을 각각 고르면 기본형도 카드형도 나온다. **편집 중에 모드를 갈아타는 알약은 두지
않는다** — 갈아탈 것이 없기 때문이다. 실서비스도 프로필 머리를 "레이아웃"으로 고르게
하고 있어 자리가 이미 있었다.

시작할 때 고르는 템플릿은 다른 얘기다. 그건 빈 캔버스를 혼자 쌓는 부담을 더는 **출발점**
이고, 들어온 뒤에는 레이아웃도 카드 면도 블록도 전부 따로 고친다(`avatar-create-1016`).

### 프로필 레이아웃 네 가지

| | 앞면 | 쓰는 이미지 |
|---|---|---|
| **원형** | 동그란 사진 + 이름 | 사진 |
| **배경만** | 이름만 (사진 없음) | — |
| **명함** | 로고(또는 회사명) + 작은 사진 + 이름·직함·연락처 | 로고, 사진 |
| **큰 이미지** | 올린 사진이 명함 앞면을 대신 | 대표 이미지 |

- **명함 비율(91:55)은 고정.** 큰 이미지도 같은 비율로 잘라 보여준다. 자르는 창은
  실서비스가 업로드 때 띄우므로 여기서는 다루지 않는다.
- **큰 이미지는 정보를 아래 별도 카드로 분리한다.** 사진 아래에 명함 앞면이 또 붙으면
  같은 사람이 두 번 소개된다. 사진이 앞면 전부이므로 **사진은 필수** — 안 올리면 명함으로
  흘러가지 않고 올릴 자리가 보인다.
- **명함·큰 이미지는 배경 사진 위로 올라탄다.** 원본이 그렇다 — 배경은 위쪽 띠만 남아
  사진이 배너가 아니라 바탕으로 읽힌다. 그래서 이 둘은 배경 가장자리가 늘 페이드다.
- **원형·배경만은 올라타지 않는다.** 배경을 덮지 않으니 가장자리도 직접 고를 수 있다.
- 실서비스는 레이아웃 네 칸이 모두 아바타 **위치** 변형(걸침 / 아래 / 가운데 / 없음)이다.
  여기서는 네 칸을 **머리 생김새**에 쓰고 위치는 떼어 냈다 — 왼쪽이냐 가운데냐는 정렬이
  이미 맡고 있고, 걸치느냐 아니냐는 배경 사진이 있을 때만 생기는 선택이라 조건이 다르다.
  걸침은 3의 **프로필 위치**로 간다.

## 2. 연락처를 명함 안으로

기존에는 연락처가 독립 블록이었다. 하지만 실서비스 공개 페이지에 연락처 섹션은 없다 —
연락처는 **명함에 적히는 것**이지 따로 선 구획이 아니다.

- 연락처를 프로필 블록에 합치고, 연락처 블록은 없앴다.
- 명함 레이아웃에서는 카드 안에 바로 나온다.
- **네 레이아웃 모두 이름·직함과 연락처를 각각 보일지 고를 수 있다.** 값은 지우지 않아도
  되므로 레이아웃을 오가도 다시 입력할 일이 없다. 큰 이미지에서 둘 다 끄면 사진만,
  명함에서 둘 다 끄면 로고와 얼굴만 남는다.
- 둘 다 끄고 세울 사진마저 없으면 **프로필 블록은 공개 화면에서 사라진다.** 꺼 둔 글은
  내용으로 세지 않는다. 편집 화면에만 자리가 남아 다시 켤 수 있다.

**회사명**도 되살렸다. 원본에 로고 대신 회사명을 글자로 세우는 경우가 있었다. 명함에서는
로고 자리에, 나머지 레이아웃에서는 직함 옆에 놓인다. 순서는 **이름 → 회사명 → 직함.**

## 3. 프로필 편집 입구를 하나로

프로필을 고치는 길이 세 갈래였다 — 블록을 누르기, 디자인 > 프로필, 배경 사진 누르기.
게다가 정렬은 두 군데에 똑같이 있었고, **레이아웃은 한 곳에서 고르는데 그 레이아웃이
쓰는 사진은 다른 곳에서 올려야 했다.**

**어느 입구로 들어와도 같은 패널이 열린다.** 순서는

레이아웃 → 이미지(배경 사진 포함) → 프로필 위치 → 정렬 → 이름·직함 → 연락처

**이름·직함과 연락처는 패널에서 바로 입력하지 않는다.** 한 줄로 두고, 들어가면 입력
시트가 따로 뜬다. 입력칸을 전부 펼치면 패널이 길어져 레이아웃·이미지가 스크롤 밖으로
밀려난다. 줄 오른쪽에 **보임 눈**이 함께 있어, 켜고 끄는 것만 할 때는 들어갈 필요가 없다 —
블록을 끄고 켜는 눈과 같은 손잡이다.

- **고른 레이아웃이 실제로 쓰는 이미지만 보여준다.** 원형이면 사진 하나, 명함이면 로고와
  사진, 큰 이미지면 대표 이미지. 거기에 배경 사진이 늘 따라붙는다.
- 이미지는 **한 줄에 썸네일 칸으로** 둔다. 비어 있으면 `+`, 채워지면 사진과 지우기.
  무엇이 비었는지 한눈에 보인다.
- 배경 사진은 **이 패널에서만** 올린다. 캔버스 위에 있던 배경 등록 슬롯은 없앴다.
- **프로필 위치는 네 칸** — 가장자리(기본 / 페이드) × 겹침(겹치지 않음 / 겹침)이다. 겹치면
  사진의 절반이 배경에 걸친다. 배경 사진을 올렸을 때만 뜨고, 늘 겹치고 늘 페이드인
  명함·큰 이미지에서는 뜨지 않는다.
- 명함에서도 보임 눈을 둔다. 끄면 로고와 사진만 남은 카드가 되지만, 그건 고를 수 있어야
  하는 모습이다 — 레이아웃마다 손잡이가 있다 없다 하면 그게 더 설명할 거리가 된다.

## 4. 블록을 다루는 법

### 추가

블록 사이에 있던 삽입선을 **전부 없애고**, **우측 하단 버튼 하나**로 모았다. 삽입선은
블록 수만큼 늘어나 캔버스를 잘게 썰었고, 배경 사진과 프로필 사이처럼 아무것도 끼면 안
되는 자리에도 끼어들었다.

버튼에는 `+`와 함께 **글자를 단다.** 동그란 `+` 하나로는 추가라는 것까지만 읽히고 무엇이
추가되는지가 없다. 그건 아이콘을 바꿔서 풀 수 있는 문제가 아니다 — 블록·레이어 모양으로
바꾸면 추가라는 뜻마저 흐려진다.

대화하기 버튼과 자리가 겹칠 걱정은 없다. 플로팅 대화하기는 **미리보기에서만** 뜨고,
블록 추가는 **편집 중에만** 뜬다. 블록 편집 시트가 열려 있는 동안에는 시트에 가려
보이지 않는데, 어차피 시트가 그 자리를 덮고 있으므로 그대로 둔다.

### 종류

실서비스 블록 목록과 대조해 정리했다.

| 블록 | |
|---|---|
| 링크 | **새로 넣음** — 버튼형 / 썸네일형 / 카드형 |
| 구분선 | 쓰지 않기로 함 |
| 연락처 | 명함 안으로 합침 |
| 프로필 | **추가 목록에서 뺌** — 페이지에 늘 하나 있다. 그래서 지울 수도 없다 |

### 보임 / 숨김

블록 편집 시트 맨 아래 묻혀 있던 것을 **블록 왼쪽 눈 아이콘**으로 꺼냈다. 오른쪽 이동
레일과 마주보는 빈 자리다.

- 보이는 블록은 흐릿한 눈 — 여러 개여도 왼쪽이 조용하다
- 숨긴 블록은 가로질러진 눈 + 본문이 물러난다
- 토글 대신 아이콘인 이유: 켜진 블록마다 브랜드색 띠가 쌓이면 "색은 사진이 낸다"는
  이 화면의 원칙과 부딪힌다
- '숨김' 배지는 두지 않는다 — 가로질러진 눈과 물러난 본문으로 이미 읽힌다
- 시트 안의 토글은 뺐다 — 누르는 자리는 한 곳
- 프로필 패널의 이름·직함, 연락처 줄도 같은 눈을 쓴다. **무언가를 숨기는 손잡이는 이
  화면에서 눈 하나뿐이다** — 스위치와 눈이 섞이면 둘이 다른 일을 하는 것처럼 보인다

## 5. 섹션 생김새 — 편집화면이 바뀌기 전으로 원복

**편집화면이 블록형으로 바뀌기 전의 카드형 명함 디자인으로 되돌린다.** 블록 편집으로
옮겨 오는 과정에서 섹션 생김새가 조금씩 어긋나 있었다. 새로 만드는 것이 아니라,
원래 카드형 명함이 가지고 있던 모습을 그대로 다시 쓴다.

섹션별로 대조해 어긋나 있던 것:

- **명함의 종이 그림자** — 카드 아래로 한 장 더 비치는 번진 그림자가 빠져 있었다
- **섹션 카드 그림자** — 있어야 하는데 빠져 있었다
- **이름 자간** — 명함 특유의 넓게 벌어진 글자가 안 나고 있었다
- **별점 색** — 브랜드 보라가 아니라 앰버
- **SNS** — 검은 사각 타일, 가운데 정렬
- **링크 목록** — 제목 한 줄 + 우측 화살표, 행 사이 구분선
- **리뷰** — 가로 카드가 아니라 세로 목록

### 이벤트 썸네일

- 비율을 고를 수 있다 — **포스터형 3:4(기본) / 정사각형 1:1 / 배너형 4:3**
- **사진이 비율에 안 맞으면 자르지 않는다.** 사진은 통째로 보이고 남는 자리는 같은 사진을
  흐려서 채운다. 포스터는 제목이 가장자리에 있는 경우가 많아 자르면 그게 날아간다.

### 카드 면

섹션이 흰 면에 올라갈지 고를 수 있다. 끄면 섹션이 페이지 배경 위에 바로 놓인다.

- **이벤트 카드와 링크는 흰 면을 유지한다.** 이벤트는 사진과 글이 한 덩어리로 읽혀야
  하고, 링크는 누르는 면 자체라 면이 없으면 눌릴 것으로 보이지 않는다.
- **링크 목록 · 게시판 · 리뷰는 목록 부분에만 아주 옅은 면**이 깔린다(제목은 면 밖).
  설정이 아니라 기본이다. 흰 카드 위에서는 저절로 안 보이고, 색을 깐 배경에서만
  나타난다 — 따뜻한 구분선이 흰 종이를 전제로 한 색이라, 색 배경 위에 그냥 놓이면
  누렇게 뜬다.

## 6. 팔로우 · 공유

원본대로 **모든 레이아웃에서 우측 상단**에 둔다. 미리보기에서만 보인다.

- 배경 사진이 있으면 그 위에 얹히고, 뒤에 어두운 그라데이션이 깔려 글자가 읽힌다
- 배경 사진이 없으면 제자리를 차지하고 공유 버튼이 밝은 쪽으로 바뀐다

## 7. 실서비스 블록 시트와 맞춘 것

각 블록을 눌렀을 때 나오는 항목을 실서비스와 하나씩 대조했다.

| 블록 | 바뀐 것 |
|---|---|
| 이벤트 | 노출 개수 **뺌**(가로로 전부 늘어놓고 밀어 본다) · 썸네일 비율 **넣음** · AI 학습 **넣음** |
| 게시판 | 정렬 **뺌** · AI 학습 **넣음** |
| 리뷰 | 그대로 |

디자인 시트 탭도 실서비스와 같이 **프로필 / 스타일 / 블록 / 대화버튼** 넷이다.


---

## 8. 페이지 탭을 없앴다

실서비스 프로필에는 **홈 · 갤러리 · 이벤트·행사 · 게시판 · 리뷰** 탭이 있고, 각 섹션의
전체보기를 누르면 그 탭으로 옮겨 간다.

**블록 편집에서는 이 탭이 설 자리가 없다.** 탭은 "그 섹션이 거기 있다"를 전제로 하는데,
블록은 순서를 바꾸고 숨기고 지울 수 있다. 블록을 지우면 가리킬 데가 없는 탭이 남고,
순서를 바꾸면 탭 차례와 페이지 차례가 어긋난다. 탭을 블록에 맞춰 자동으로 고치더라도
사용자가 만질 수 없는 줄이 하나 더 생기는 셈이다.

그래서 **탭을 두지 않고, 각 섹션의 전체보기가 그 역할을 대신한다.** 홈 한 장이 길어지는
대신, 프로필에서는 각 섹션이 앞부분만 보여주고 나머지는 전체보기로 넘긴다.

## 9. 적용된 화면 — 프로필과 전체보기

편집 결과가 실제로 어떻게 보이는지 세 파일로 떼어 두었다.

- `profile-view.html` — 카드형 명함이 적용된 공개 프로필
- `profile-view-plain.html` — 같은 프로필을 **카드 면 없이** 둔 경우
- `profile-view-all.html` — 각 섹션의 전체보기 네 화면

프로필 화면에는 **링크 블록 세 종류를 하나씩** 놓아 생김새를 견줄 수 있게 했다.

### 섹션 액션

이벤트·게시판·리뷰에는 **이벤트 추가 / 글쓰기 / 리뷰 작성**이 제목 줄 오른쪽에 붙는다.
브랜드색을 채운 큰 버튼이 아니라 **테두리만 두른 작은 알약**이다 — 페이지에서 가장 눈에
띄어야 하는 것은 올린 내용이고, 이 버튼들은 그다음이다. 갤러리에는 두지 않는다.

### 전체보기

탭을 없앴으므로(8) 전체보기는 **각자의 화면으로 나간다.**

| 화면 | |
|---|---|
| 갤러리 | 올린 것을 전부 격자로 |
| 이벤트 | 다가오는 행사 · 지난 행사로 나눠 **리스트로** |
| 게시판 | 제목 아래 미리보기 한 줄과 작성자·날짜까지 |
| 리뷰 | 평점이 한 덩어리로 맨 위, 그 아래 받은 후기 |

**이벤트와 게시판 목록에는 흰 면을 깔지 않는다.** 줄 사이 구분선만으로 나누고 배경 위에
바로 놓는다. 리뷰도 평점은 면 없이 서고, **면을 갖는 것은 받은 후기 목록뿐이다.**

---

## 되짚어 둘 원칙

- **보이는 것을 눌러 고친다.** 같은 것을 두 군데서 고치게 두지 않는다.
- **없는 선택지는 만들지 않는다.** 실서비스에 없는 설정을 새로 들이지 않는다.
- **설명을 덧붙여야 읽히는 화면은 문구가 아니라 구조를 고친다.**
- **이름이 결과와 맞아야 한다.** "카드 면 없음"이 실제로 면을 남기면 안 된다.
